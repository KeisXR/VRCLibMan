# アセット更新記録

「ログ → アセット更新」には、確認待ちの商品と検出履歴を表示する。未確認の候補があるときは、左メニューの「ログ」と「アセット更新」タブに件数を出し、「ログ」から直接このタブを開く。左メニューを折りたたむとログのアイコンに点を出し、ツールチップに件数を表示する。候補の通知からもこのタブを直接開ける。確認対象と自動確認の切り替えは設定にある。確認済みにすると候補一覧と件数から外れるが、履歴は残る。

履歴は直近200件。時刻はVRCLibManが差分を検出した日時で、BOOTHの公開日時とは異なる。商品・バリエーション・ファイル名と、数値IDがある場合は `https://booth.pm/downloadables/<ID>` を表示する。外れたファイルと追加されたファイルは別々に列挙し、複数ファイルを推測で一対一に対応付けない。期限付きURLやローカルパスは保存しない。説明の変更は変更の有無だけを記録する。

ライブラリ全体を読み込めたときは前回の完全なファイル一覧と比較する。一部の読み込みでは明示的に見つかった追加だけを記録し、掲載されなかったファイルを削除と判断しない。無料ファイルの公開情報はライブラリの一覧と別に比較する。最初の完全な観測より前のファイルや日時は推測しない。従来の更新は確認待ちとして引き続き見られる。

確認中はサイドバーのボタンの下に、処理した件数と対象数、進捗バーを表示する。サイドバーを折りたたむと進捗バーとツールチップで確認できる。BOOTHへは1件ずつ問い合わせ、間隔を空けるため、全商品を対象にすると数分かかることがある。自動確認は許可され、確認期限が来た商品がある場合にだけ実行する。手動・自動の確認は同時に実行しない。候補通知は確認終了後にまとめ、同じ候補を定期確認のたびに通知しない。

## ダウンロードしたいファイルが BOOTH に無いとき

作者がファイルを差し替えると、古いダウンロード番号は BOOTH で 404 / 410 になる。内蔵ブラウザでのダウンロードがこの応答で失敗したときは、失敗の帯の代わりに「このアセットを更新しますか？」を出す（`src/components/AssetUpdatePrompt.tsx`）。サイドバーの「ダウンロード」には、これまでどおり失敗の行が残る。

- **更新する** は、先頭の 1 件について、BOOTH のライブラリを読み直し（ライブラリ全取得と同じ）、その商品で新しく見つかったファイルのうち、手元にもリモートにも無いものをダウンロードする。同じバリエーションに新しいファイルがあればそれだけにし、無ければ（バリエーション名が変わったとき）その商品の新しいファイルをすべて受け取る。選び方は Rust の `view::update_download_targets`。
- **すべて更新する（N件）** は、BOOTH に無かったファイルが 2 件以上たまっているときだけ出し、たまっているすべてを同じように更新する。読み直しは 1 回にまとめる。
- **閉じる**（Esc、外側のクリック）は、たまっている確認をすべて閉じる。

対象は、本人が押して BOOTH に無かったファイルの商品だけで、ライブラリ全体の新しいファイルは受け取らない。一括のダウンロードを作らないため（AGENTS.md の「続けて作らないもの」）。受け取り中のファイルがあれば、終わってから読み直す（全取得は受け取り中には始められない）。前の読み直しより前に失敗したファイルは、読み直さずに探す。読み直しがログイン切れなどで止まったとき、中止したとき、新しいファイルが見つからなかったときは案内だけを出し、ダウンロードしない。更新で始めたファイルも BOOTH に無ければ、もう尋ねずに失敗として出す。
