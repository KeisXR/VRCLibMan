# 購入履歴

左メニューの「購入履歴」で、BOOTH で購入した注文を新しい順に見る画面である。注文日時、金額、ギフトとして贈ったかどうか、商品ごとのラベルを扱い、対応アバターごとに件数と金額を数える。読み込みは任意で、使わなくてもほかの機能は変わらない。

## 画面

| 場所 | 中身 |
| --- | --- |
| `#/purchases` | 「履歴」タブ。注文ごとに日時、注文番号、お支払金額と、その下に商品を並べる。1 ページ 50 注文 |
| `#/purchases/summary` | 「アバター別」タブ。期間（全期間か年）ごとの件数と金額 |
| `#/purchases/group/<枠>` | アバター別の行から開いた履歴。`avatar:<id>`、`generic`、`unclassified` で絞り込む |

- 商品の「アセットを見る」「ワールドを見る」「アバターを見る」は、購入した商品をアプリの中で開く。ライブラリにあり、除外しておらず、カテゴリが決まっている商品だけに出す（`purchases::library_link`）。アセットとワールドは `#/assets/item/<商品ID>` / `#/worlds/item/<商品ID>` で「すべて」の一覧を開き、その商品を中央へ送って選択枠（`--selection-outline`）で示す。アバター本体は `#/avatar/<id>`。贈っただけの商品はライブラリに無いので出ない。
- 注文が 1 件も無いときは、読み込みの説明だけを出す。内蔵ブラウザが無効なら設定への案内を出す。
- 「金額を表示」は `settings.purchase_show_prices`（既定オフ）に保存する。オフのあいだは履歴と集計のどちらにも金額を出さない。
- 検索欄はこのタブの中だけで使い、上部の「ライブラリを検索」とはつながらない。全注文に対して探してから、結果を 50 件ずつに分ける。対象は商品名、ショップ名、商品 ID、注文番号、ラベル名、アバター名、「ギフト（贈った）」で、空白で区切った語をすべて含む注文を出す。NFKC で半角カナや全角英数をそろえる。
- 絞り込みはラベル（「ギフト（贈った）」を含む）、アバター別の枠、年。検索欄の横の「絞り込み」で開閉し、閉じている間も使っている条件の数を「絞り込み（N）」と出す。アバター別の行から開いたときは、条件が見えるよう開いておく。
- 商品の「ラベル」で付け外しする。ラベルが多いときは一覧だけをスクロールし、新しいラベルの入力は常に見せる。下に場所が無ければ上に開く。外側のクリックか Escape で閉じる。見た目は [デザインガイド](design/README.md#購入履歴)。
- 日時は BOOTH の表示どおりの日本時間を秒まで出す。端末のタイムゾーンへは変換しない。

## データの取り方

内蔵ブラウザだけを使う。拡張機能からは送らない（拡張のリワーク後に検討する）。

### 「購入履歴を読み込む」

1. 表示中の内蔵ブラウザのタブで、`https://accounts.booth.pm/orders` を `?page=` で 1 ページずつ開き、一覧を読む。
2. 続けて、詳細が未取得の注文の `https://accounts.booth.pm/orders/<注文番号>` を新しい順に 1 件ずつ開いて読む。

ギフトとして贈ったかどうかは、一覧に出ず詳細にしか出ないことがある。このため一覧だけで済ませず、全注文の詳細を一度ずつ読む。金額の内訳も詳細にしかない。

- 間隔は「ライブラリ全取得」と同じ `booth_page_interval_ms`（1000 / 500 / 250ms、初期値 1000）で、並列にしない。ライブラリ全取得と同時には走らせない（同じタブを動かすため）。ダウンロード中も始めない。
- 移動先は一覧と注文詳細だけ（`purchase_walk::orders_path`）。ログインや年齢確認、それ以外のページに着いたら止める。年齢確認は自動で通過しない。
- 中止は次のページへ移る前に効く。読んだところまでは保存する。
- 一覧を一度最後まで読むと `purchase_history_complete` を立てる。以後は、新しい注文も状態の変わった注文も無いページで一覧を止め、詳細の読み残しだけを読む。最初の一巡を中止したときは印を立てず、次も最後まで読む。
- 進捗（`browser-purchases`）と記録には件数とページ番号だけを書き、商品名は書かない。

### 購入完了ページ

内蔵ブラウザで本人が開いた `https://checkout.booth.pm/orders/<注文番号>` を、商品の自動登録（[AGENTS.md](../AGENTS.md) の「内蔵ブラウザ」）と同じ条件で確かめたあと、その注文を購入履歴に入れる。設定の「取得したアセットの自動登録」がオンのときだけである。購入完了ページには日時と金額が無いので、同じログインの隠した子 WebView（`booth-order-reader`、1px、非表示）を購入完了ページと同じ窓に作り、その注文の詳細を 1 回だけ読んで閉じる。ダウンロードと新しい窓は拒否する。読めなかったときは「詳細は未取得」のまま残し、次の読み込みで埋める。

Linux では右パネルが GtkOverlay への重ね合わせなので、隠した子 WebView を足さない。詳細は次の読み込みで埋める。

### 本人が開いた購入履歴のページ

内蔵ブラウザで本人が購入履歴か注文詳細を開いたときも、自動登録がオンなら、そのページだけを読んで保存する。ページの移動はしない。

## 読むものと読まないもの

ページを読むのは `src-tauri/src/purchase_extract.cjs` で、Rust（`purchase_walk::parse_*`）がもう一度値を確かめてから DB に入れる。

| 読む | 読まない |
| --- | --- |
| 注文番号、状態の印（`.order-state`）、注文日時、お支払金額 | お支払方法 |
| 商品 ID、表示名（バリエーションを括弧で含む）、ショップ名、商品代金、BOOST、数量 | 住所、氏名、電話番号 |
| ギフトかどうか（真偽値だけ） | ギフト用 URL、受け取り状況 |
| | ダウンロード URL、ファイル名、サムネイル URL |

- 状態は「確定」「キャンセル」「支払い待ち」に分け、確定した注文だけを残す。キャンセルと支払い待ちになった注文は行ごと消す。
- ギフトの判定は、詳細ページの中で、商品名・ショップ名・ダウンロードの並び（ファイル名）を除いた文字、`class`、`title`・`aria-label`・`alt`・`name` などの属性に「ギフト」か `gift` があるかで決める。ギフトの注文が手元に無く、実際のギフト注文の表示では確かめていない。誤ったときは注文ごとに「贈ったギフト」「自分用」を手で選べ（`purchase_orders.gift_override`）、「自動判定」に戻せる。
- 一覧と詳細で注文日時の秒がずれることがある（実例で 1 秒）。詳細の値を残す。
- 商品名に「¥」や「円」が入ることがある（例：【500円】）。金額は商品名の外の行からだけ読む。
- 一覧のページ送りで、同じ注文が別のページにもう一度出ることがある（実例で 124 行のうち重複 2 行）。注文番号で 1 件にまとめる。

## 保存

DB 版 12 で次の表を足した（`purchases::TABLES`）。既存のライブラリは空から始まる。

| 表 | 中身 |
| --- | --- |
| `purchase_orders` | 注文番号、注文日時、お支払金額、ギフトの自動判定と手動の指定、一覧の表示名、詳細を読んだ日時、記録元（`history` / `checkout`） |
| `purchase_items` | 注文ごとの商品。`(order_id, booth_id, name)` で一意 |
| `purchase_labels` | 利用者が作るラベル。名前は 30 文字まで、100 個まで、重複なし |
| `purchase_item_labels` | 商品とラベルの対応 |

- 購入履歴の商品は `products` に足さない。ライブラリに無い商品（贈ったギフト、実物のグッズなど）は購入履歴の中だけにある。
- 購入完了ページの記録はバリエーション名を持たないので、詳細を読んだ名前の行に置き換わる。同じ商品のラベルは新しい行へ引き継ぐ。

## 商品と金額の表示

商品名と購入した対応版を表示し、商品の対応範囲にある全アバターのチップは出さない。1商品で、お支払金額が商品代金とBOOSTの合計に一致する注文は、商品の行だけに金額を表示する。複数商品や送料・手数料のある注文では、「商品代金」と「お支払」の見出しを付けて区別する。BOOSTは商品代金と分け、金額不明と0円も区別する。「金額を表示」がオフなら両方を隠す。

## アバター別の集計

- 本体は本体のアバターに、購入した対応版が1体に決まる商品はその枠に数える。同じ素体には広げない。
- 複数の対応版が1つの購入で手に入る商品は「複数アバター対応」に1回だけ数え、金額を推定配分しない。
- 対応版を判別できない場合は「対応版未設定」に数える。
- 標準は所持アバターの枠だけを表示し、「未所持アバターも表示する」で切り替える。特殊な枠は常に表示する。
- 上部の合計は表示の絞り込みと関係なく全購入を1回ずつ数える。贈ったギフトは枠に入れず、合計の内訳に残す。
- 送料・手数料はアバター別集計に含めず、金額不明の商品は件数と不明件数を表示する。

判定規則と保存は [購入した対応版](purchased-editions.md) を参照。

## データ移行

データ移行の ZIP（版 4）の `purchases` に、注文、金額、ラベル、「金額を表示」の値を入れる。形は [データ移行](remote-sync.md) にある。

## 未検証

- 内蔵ブラウザ（WebView2 / WKWebView / WebKitGTK）での「購入履歴を読み込む」の通し。抽出は Chrome で開いた実際の購入履歴と注文詳細で確かめた（[検証記録](verification.md#購入履歴2026-11-11)）。
- 購入完了のあとに隠した子 WebView で詳細を読む流れ（Windows・macOS）。
- 実際のギフト注文、支払い待ちの注文、実物のグッズと送料のある注文、複数商品の注文の表示。
