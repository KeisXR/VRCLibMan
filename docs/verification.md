## Linux AppImage 対応の実装確認（2026-10-30）

対象は `2099ef5c0ecc3b849b2a5ff110229555f5e76c6e`（v0.1.14）を基準にした Linux 対応の作業差分です。実行環境は Debian 13 x86_64、Rust 1.99.1、Node.js 24.19.0、GTK 3.24.49、WebKitGTK 2.54.0 です。配布基準の Ubuntu 22.04 とは異なります。既存ライブラリには触れず、新しい一時データで検証しました。

- `npm run build` 成功、`npm test` 74件成功。
- `cargo test --offline --locked --manifest-path src-tauri/Cargo.toml --lib` は239件成功・1件ignore。XDG の日本語ダウンロード先を実際の設定ファイルから読み、既知のステージング先以外を拒否すること、保存済みの常駐設定が真でも Linux で無効になること、両 CPU の AppImage だけ更新を許可する判定を含みます。
- `npm run dev` と Chromium で Linux の能力応答を再現し、設定画面の常駐・ログイン起動の両スイッチがオフ・無効で、説明文が表示され、ページエラーがないことを確認しました。これは見本の UI 確認です。
- Linux のネイティブビルドが成功。URL 登録用コマンドを意図的に失敗させても、警告を出して初期ウィンドウの表示へ進むことを確認しました。ホストには WebKit の補助プロセスが通常とは異なる場所に導入されているため、その後の raw バイナリ実行は継続できませんでした。
- x86_64 の試験 AppImage（118,516,216 bytes）を生成し、試験用公開鍵の埋込み、署名の正当性、署名された版 0.1.14 の一致、改ざん拒否を確認しました。ホストの特殊な sysroot 配置に限り、試験用設定で WebKit の補助プロセスを追加同梱しています。製品の設定とは分離しています。
- その AppImage を一時データと仮想 X11 画面で起動し、URL 登録用コマンドが失敗しても継続すること、保存済み常駐・ログイン起動が真で自動起動の引数があっても実メインウィンドウが表示され、閉じるとプロセスが終了コード0で終了することを確認しました。FUSE の代わりに展開実行を使った起動確認です。
- workflow YAML の解析、AppImage 設定、更新用の4対象・署名欠落拒否を確認。既存の2対象だけの下書きは、そのタグの生成スクリプトを使って再生成できることも確認しました。

主要ディストリビューションの実動作、両 CPU の署名付き次版への更新・再起動・DB 保持は未確認です。BOOTH への実ログイン、実ファイルの取得・移動、実モデルによる分類もこの実装確認の範囲外です。

## 今後の記録方法

配布前の確認では、対象コミット・アプリと拡張の版・OS・端末構成・実施日・手順・結果を記録してください。見本、テスト、実機で確かめた範囲を区別します。

- 分類規則: 新しい一時 DB、サンプル、必要に応じた実ライブラリ。実商品の本文や年齢制限のある本文は記録へ貼らない。
- 拡張と内蔵ブラウザ: ログイン済みライブラリの商品数、全取得と中止、ログイン切れ、ギフト、公開商品ページ。
- 配布物: Windows / Apple Silicon Mac でインストール、起動、サムネイル、ファイル移動・コピー、バックグラウンド動作。
- 更新: 署名付き次版を使った実インストーラでの更新、ライブラリ・設定の引き継ぎ、失敗時の再試行。手順と自動テスト範囲は [配布とアプリ内更新](updater.md) を参照。

見本データの画面が動くことは、名前解決やファイル照合の正しさの証明にはなりません。Rust の規則テストと実機確認を、それぞれの範囲の証拠として扱います。
