- Windows: 設定の「クラウド(APIキー)」で APIキーを保存すると Windows の資格情報マネージャーに `app.vrclibman.desktop` / `cloud-classifier-api-key` として入り、アプリの再起動後も「保存済み」になること。「削除」で消えること。`vrclibman.db` の `settings` 表、`booth-browser.log`、書き出し JSON、バックアップにキーが含まれないこと。
- Mac: 同じ操作でキーがキーチェーンに保存・削除されること（キーチェーンの許可ダイアログの出方も確認する）。
- 実際のプロバイダ（OpenAI の `https://api.openai.com/v1`、xAI の `https://api.x.ai/v1` など）に、本物のキーで接続テストと分類が通ること。`response_format` を受け付けないモデルで 400 のあと 1 回だけ再送されること。誤ったキーで「認証失敗」、存在しないモデルで「モデルなし」または接続テストの「一覧にありません」になること。回数制限（429）で待ってからやり直し、上限を超えると「回数制限」になること。ここまでは単体テストとプレビューの見本だけで、実際の API には送っていない。
- クラウド分類中に、年齢制限の商品が送られず、Ollama や Apple が使えないときは未分類のまま残り、`booth-browser.log` に `クラウド送信見送り <ID末尾4桁> 年齢制限` だけが残ること。
- 分類後の `booth-browser.log` に、ルールで拾えないカテゴリが `未対応カテゴリ id=<N> name=<カテゴリ名> parent=<親カテゴリ名>` として同じ組み合わせで 1 回だけ残ること。商品名、説明、タグ、店舗名は出ないこと。ID 157、142、6 はここで名前が分かってから割り当てる。
