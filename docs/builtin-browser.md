# 内蔵ブラウザ

内蔵ブラウザ（`src-tauri/src/browser*.rs`、右パネルと別窓のネイティブページ、ライブラリ全取得、ファイルのダウンロード、購入とダウンロードの自動登録）の契約。この領域を変更するときは先に読む。領域をまたぐ境界の要約は [AGENTS.md](../AGENTS.md#内蔵ブラウザ) にあり、食い違うときはこの文書を直して合わせる。

右パネルの実装とデザインの詳しい説明は [右パネル](right-panel.md)、購入履歴の読み込みは [購入履歴](purchase-history.md)、拡張との違いは [拡張の仕様](browser-extension.md#内蔵ブラウザとの違い) にある。

## 購入とダウンロードの自動登録

内蔵ブラウザの `browser_auto_register` は既定オン（既存DBにも設定行を `INSERT OR IGNORE` で追加）。内蔵ブラウザ自体の既定オフとは別。購入を代行せず、本人が開いた `https://checkout.booth.pm/orders/<注文番号>` で購入完了の見出し・`xrcloud:event=purchased`・注文番号の一致を確認し、`data-tracking=item` の専用商品データだけを登録する。おすすめ商品やシェアリンクから購入商品を推測しない。複数のバリエーションは商品IDで重複を除く。購入ページの情報は疎なので、既存商品の説明や手動分類は上書きしない。

本人のダウンロードリンクのクリックと、同じタブのネイティブ保存完了を対応付ける。ファイルIDから商品とバリエーションが一意に決まるパッケージだけ登録する。自動取得・ページ移動はしない。保存先はダウンロードフォルダの一意な `VRCLibMan-*` ディレクトリに固定し、macOSで完了パスが無いときも既知の保存先を使う。自動整理オンなら従来の `VRCLibMan/<商品ID>/` ステージング検査を経てライブラリへ移し、オフならダウンロード先のまま登録する。未特定や失敗したファイルは推測でひも付けない。

初回検知の未確認商品は settings の商品ごとの seen/pending キーで重複と分類待ちを保存する。分類ダイアログはアセットのジャンル・ワールド・アバター本体を既存の手動分類コマンドで確定する。確定は手動の固定になるので、決め打ちの初期値は置かない。読むだけの `product_genre_suggestion`（自動の分類の結果、BOOTH のカテゴリとタグ、タイトルと説明の規則の順。手がかりの無い「その他」は候補にしない）の候補を出どころと一緒に選んでおき、候補が無ければ種類と分類先を本人が選ぶまで確定できない。Esc と「後で分類する」は今出ている未分類を後回しにするだけで、登録と pending は残し、ジャンルは決めない。後回し中は左下の再開ボタンから続け、新しい未分類が届いたらダイアログを開き直す。保存中にダイアログが閉じたときも同じ後回しにして再開ボタンを出す。外側のクリックでは閉じない。保留・保存失敗で待ちを消さず、再起動後もダイアログで続ける。機能をオフにしても既存登録・分類待ち・ログインを削除しない。オフ中の新規登録・ファイル整理は行わない。

## 有効にしたときの動作、ログイン状態、アカウント表示

利用者向けドキュメントは内蔵ブラウザを推奨し、拡張はアプリ内でのログイン・閲覧を使わない人向けの代替手段として案内する。保存値の既定は拡張機能のままで、初回セットアップでは本人に選ばせる（[読み込み方と接続情報](../AGENTS.md#読み込み方と接続情報)）。有効にすると、Windows / macOS は右パネル、Linux は別ウィンドウで `https://accounts.booth.pm/library` を開く。ログインとページ移動はユーザーが行う。今見えているライブラリのページだけを `extension/extract.js` の `extractPage` で読み、ファイルのインポートと同じ `import_export_json` に渡す。ページの自動移動は「ライブラリ全取得」と「購入履歴を読み込む」、内蔵ブラウザ有効時の手動「今すぐ確認」を押したときだけである。表示中のページとは別に、購入完了のあとと商品カードの「購入したファイルを読み込む」では、隠した子 WebView がライブラリを最大 3 ページ読む（[購入履歴](../AGENTS.md#購入履歴)）。年齢確認の URL はインポートを拒否し、確認を自動で通過させない。セッションはメイン画面とは別の WebView データストアに置く。本人が1件のファイルを「ダウンロード」操作時のみ、最初の `https://booth.pm/downloadables/{番号}` 向けリクエストに使うため Cookie を取得する。Rust の `quiet.rs` はリダイレクト先が BOOTH の同一ホストやサブドメインでも初回用 Cookie を再送しない。転送先の認証が必要なら失敗として扱い、元の Cookie を流用しない。ログアウト時は専用のログイン状態を消去する。`library.sqlite` は消さない。サイドバーのアカウント表示は、ログイン済み、ページが明示した未ログイン、確認できない、を分ける。DOM が未準備、タイムアウト、通信や読み取りの失敗は未ログインにしない。失敗したときは直前に取れたアカウント表示を残して「確認できません」とし、一度も取れていなければ「状態不明」とする。隠した確認用 WebView を作った直後には、結果を返すスクリプトを実行しない。読み込み完了を待ってから DOM を見る。固定の待ち時間だけでは待たない。確認の待ちは上限を設け、UI スレッドを止めない。古い確認結果は新しい状態を上書きしない。macOS では確認用 WebView を表示タブと別に最大1つ保持し、タブを閉じても捨てない。タブ一覧には出さず、フォーカスも奪わない。BOOTH 以外のタブだけのときも、見ているページは動かさずに確認する。データストアは固定の `BOOTH_DATA_STORE_ID` のまま。確認用にだけ `BackgroundThrottlingPolicy::Throttle` を付ける。明示ログアウトは確認を止め、同じデータストアの WebView をすべて閉じてから消去し、消去中は確認用を作り直さない。WebKit のプロセスが終了したら、ブラウザを開かずに作り直して確認できる。Windows は表示中に二本目を作らず、確認のたびに隠した窓を捨てる。

macOS の終了ハンドラは Tauri 標準の自動再読み込みを置き換えるため、確認用以外の WebView（メイン画面・操作バー・表示タブ）は終了時に再読み込みする。

## 右パネルのネイティブページ

右パネルのネイティブページは、DOMで測った表示域の内側に収まる整数CSSピクセルの矩形へ置く（左・上は切り上げ、右・下は切り下げ）。macOSでは `NSWindow.contentLayoutRect` をページのsuperviewの座標へ変換し、その上端をDOMの原点として配置する。Tauriの通常タイトルバーもFullSizeContentViewを使うため、親ビュー全体の上端はDOMの原点と一致しない。タイトルバー高の固定値や画面倍率を掛けず、リサイズ・再ドックのたびに実際の内容領域を読む。埋め込みWKWebViewの `clipsToBounds` も有効にする。別窓のoverlayタイトルバーの配置は従来どおりである。

狭い窓（と利用者が浮かせたとき）の右パネルは、アプリの窓の中に浮かぶ小窓で、常に窓の内側に収める（`src/floatingPanel.ts` の `clampFloatRect`）。中のネイティブページが窓の外へ出ないようにするため。動かす・大きさを変える間はページを隠し、置いたら測り直す。詳しくは [右パネル §6.3](right-panel.md#63-浮かぶパネル狭い窓)。

右パネルのタブは幅0に潰さず、どのタブにも押せる最低幅を残し、入りきらない分はタブ列を横にスクロールさせる。潰れたタブは閉じたように見え、隣のタブを押し間違えるため。別窓のタブは選択の処理中も `disabled` にしない（フォーカスが外れ、続く矢印キーが届かない）。詳しくは [右パネル §10.2](right-panel.md#102-寸法)。

右パネルのタブ操作で App とページを描き直さず、UI スレッドへの往復を増やさない（速い CPU でもタブの移動が重かったため）。タブは `RightPanelProvider`、開閉と幅は App（`useRightPanelState`）が持ち、商品一覧は `useRightPanelPreview` だけを読む。ブラウザの状態は `browser-state-changed` が番号（`revision`）付きで運び、各窓は `src/browserStore.ts` の写し1つだけを使って古い番号を捨てる。部品ごとに読み込みやポーリングを足さない。ネイティブページの配置は変わった分だけ送り（`place_view`）、窓のリサイズ・倍率の変化・別窓との移動では送り直す。詳しくは [右パネル §2.6](right-panel.md#26-速さのための決まり)。

## 一般サイトの閲覧、タブ、表示先

一般の http / https サイトも閲覧でき、URL入力・タブごとのネイティブ履歴・再読み込みと停止・ブックマークバーがある。外部ページは `booth-tab-N` の子 WebView、アプリ製の操作バーは `booth-toolbar-N` の別 WebView で、外部ページにローカルアプリの capability は与えない。窓のラベルは `booth-win-N`。アプリ内部の URL と認証情報付き URL は開かない。BOOTH のページ抽出はネイティブの現在 URL を先に検査し、他サイトの DOM を読まない。全取得・ダウンロード中はタブ変更と手動移動を止める。全取得は開始時の tabId を固定し、途中で別の窓の選択中タブへ切り替えない。`browser_tabs.rs` はタブと、それが所属する表示先（右パネルか `window-N`）の並びと選択を持つ。`browser_surface.rs` は各表示先の窓と矩形でネイティブ配置する。右パネルと複数の別窓は同時に開ける。各表示先が自分の並びと選択中タブを持つ。操作は、その操作を出した窓の選択中タブへ作用する。ページから開くタブは、発生元タブの表示先に足す。BOOTH / pixiv のログイン用の別窓要求は元のタブで開く。`BrowserChrome.tsx` はアドレスバーとブックマークの操作部分である。右パネルではページのタブ列を描かない。別窓の操作バーだけが、その窓のページタブ列をタイトルバーに出す。Windows・macOS・Linux（`panel_supported()` は `cfg!(any(windows, target_os = "macos", target_os = "linux"))`）では、右パネルで選択中のページを `main` 窓の子 WebView として置く（`Window::add_child`、`unstable`）。プレビューとファイルと各ページは同じタブ列に並ぶ。ページを選んだときだけ、その下にアドレスバーを出し、さらに下の表示域へネイティブ WebView を置く。表示域は `getBoundingClientRect` で測り（ResizeObserver・resize・MutationObserver・500ms の確認）、`browser_action` の `panelArea`（CSS px、`main` からだけ受け付ける）で渡す。ネイティブ WebView は DOM で隠す。ドラッグは移動距離でクリックと区別する。ポインターの捕捉（`setPointerCapture`）は移動が閾値を超えてから行う。押した時点で捕捉すると、Chromium（WebView2）は click をタブのボタンではなく捕捉したタブ列へ送るため、クリックでタブを切り替えられなくなる。Escape `Destroyed` は移動済みのタブや他の窓を消さない。タブを閉じるのはそのタブだけ。別窓を閉じるとその窓のタブだけを閉じ、最後のタブでその窓を閉じる。右パネル全体を閉じてもページは破棄せず隠す。新しいセッションは、パネル対応・メイン窓が見えている・その起動中に別窓へ出していない、のときに右パネルで始め、Rust は `browser-panel-requested` を `main` へ送ってそのページタブを選ばせる。矩形が届くまでタブは隠す。パネルのホストはメイン窓を所有せず閉じない。メイン窓が壊れたら、パネルに残っているページだけを `handle_window_event` で閉じる。別窓へ出した選択はメモリだけで保存しない。右パネルの設定にはページの URL もタイトルも保存しない。保存するのは固定タブ（`preview` と `files`）の種類と選択位置だけである。旧設定の `browser` は読み捨て、ページタブへは単一タブの規則を適用しない。Linux の右パネルは GtkOverlay の主子でメイン画面を全面に保ち、その上にネイティブのページだけを配置する。余白は CSS ピクセルをそのまま論理ピクセルとして使い、倍率を掛け直さない。macOS は同じ子 WebView で、表示域の CSS ピクセルを論理ポイントとして扱い、上記の内容領域を基準に配置する。wry は子 WebView の幅と高さを整数ポイントに切り捨てるので、渡す前に四捨五入する。倍率は掛け直さない。子ビューの自動リサイズはパネル矩形に追従しないため、メイン窓のリサイズと表示倍率の変化では、最後に受け取った矩形を置き直す。別窓との移動は同じ WebView の `reparent` ## 表示倍率

ページの表示倍率は25%〜500%、初期値100%で、タブごとに保持する。操作バーのズームと Ctrl / Command の ＋・−・0 は外部ページの WebView にだけ作用し、操作バーは拡大しない。ネイティブの倍率変更も状態へ読み戻す。ナビゲーションと別窓への移動では倍率を残し、終了では保存しない。右パネルの操作バーには通常カードの `.panel` 用の padding と margin を適用しない。空の状態表示欄は描画せず、別窓のページ配置には操作バーの実測した外寸を使う。

## 強制ダークモード

強制ダークモードは `settings.browser_force_dark`（既定オフ）。設定の行として `INSERT OR IGNORE` で足し、スキーマ版は変えない。設定画面の「BOOTH の読み込み方」で内蔵ブラウザが有効なときだけ出す。オンのとき、表示用のページ WebView（`booth-tab-N`。右パネルと別窓は同じ `mount_tab`）にだけ CSS を入れる。`html` に `filter: invert(1)` を掛け、白い背景は黒に、黒い文字は白になる。`img`・`video`・`canvas`・`embed`・`object`・画像入力・`svg image` と、インラインの style で `url(` の背景画像を持つ要素（`html`・`body` を除く）には同じ `invert(1)` をもう一度掛け、画素を元の色に戻す。BOOTH の商品カードは背景画像で描かれるため。その内側の画像系にはフィルタを掛けない（[右パネル §10.5](right-panel.md#105-強制ダーク内蔵ブラウザのページ)）。YouTube の埋め込み iframe（`youtube.com/embed/`・`youtube-nocookie.com/embed/`）も同じく打ち消す。スクリプトは最上位のフレームだけで動き、子フレームでは何もしない。ページの反転が子フレームにも掛かるので、中でもう一度反転すると動画や画像が反転に戻るため。`youtube.com`・`youtube-nocookie.com` とそのサブドメインのページは独自のダークテーマを持つので反転しない。`invert(1)` は二回で元に戻る。`hue-rotate(180deg)` は色が 0 か 255 で切れると打ち消せず、青や赤がずれるため使わない。画像以外の色付きの文字やボタンは色相が反転する。注入は `document.adoptedStyleSheets`（使えないときは同じ CSS の `style` 要素）で、文書開始の初期化スクリプトと読み込み完了時の評価の両方で行う。切替は再起動不要で、開いているページにはすぐ評価する。タブを開いた時点の初期化スクリプトは、その後の切替より古いことがあるので、移動後は読み込み完了時に今の設定へ合わせる。そのあいだ元の色が一瞬見えることがある。確認用の `booth-probe`、操作バー、メイン画面には入れない。Cookie、ログイン状態、ページの storage には触れない。WebView2 の `WebContentsForceDark` は環境全体に掛かり、確認用にも効き、切替に再起動が要り、画像が元の色のままになる保証もないため使わない。Windows の WebView2 での見た目は実機未確認。macOS と Linux のネイティブ WebView も未検証。

## 別ウィンドウ

ブラウザの別ウィンドウはタブ列をタイトルバーとして使う。Windows／Linuxは decorations を無効にして、ローカルの操作バーだけに移動・最小化・最大化・閉じる権限を与える。Macは overlay と hidden_title を使い、標準ボタンのためにタブ列左側を空ける。埋め込み表示にはウィンドウ操作とドラッグ領域を出さない。Windows／Linuxのネイティブメニューは hide_menu で隠し、ショートカットの登録は残す。Linuxのメニュー項目は非表示だとアクセラレータも無効になるため、子WebViewのキーイベントをネイティブで受け、同じ dispatch_shortcut へ渡す。別ウィンドウのReact側ではショートカットを二重に処理しない。子WebViewでは自動の枠リサイズ処理が付かないため、Windowsは set_resizable で初期化し、Linuxはネイティブの外周イベントで補う。

## ライブラリ全取得

独立したブラウザ画面は無い。「ライブラリ全取得」は内蔵ブラウザが有効なときだけインポート画面の「1. BOOTH から読み込む」に出し、アクセス間隔と診断は設定の「BOOTH の読み込み方」に置く。旧 `#/browser` はインポート画面へ転送する。開いているページ1件の読み込みはブラウザ操作バーの「インポート」だけで行う。拡張の「すべて読み込む」と同じく、`https://accounts.booth.pm/library` を `?page=` で 1 ページずつ読み、続いて `https://accounts.booth.pm/library/gifts`、そのあと `https://accounts.booth.pm/library/free_downloads` を同じ読み方で読む。間隔は SQLite の `booth_page_interval_ms` で指定した1000 / 500 / 250ミリ秒（初期値1000）で、並列にしない。250msはUIで高リスク確認を行う。各ページは `extractPage` で読み、まとめて `import_export_json` に渡す。ファイルのダウンロードはしない。中止は次のページへ移動する前に効く。ログイン切れ（ライブラリ、ギフト、無料ダウンロード以外のページ、ログインへの移動）か年齢確認の URL では止まり、年齢確認の URL へは自分からは移動しない。終わりに商品数、ファイル数、名前のあるファイル数、名前の無いファイル数を出す。記録と進捗に商品名やクエリは残さない。無料ダウンロードで `isFree` が無い商品は無料として保存する。ライブラリの「非公開」は `products.unpublished`（DB版5）に残し、説明が「公開終了（取得できず）」の商品とは別に扱う。非公開だけではカテゴリをその他にしない。全取得のあと、`booth_detail_at` が空で年齢制限でない商品だけ、公開の `https://booth.pm/ja/items/{id}.json` を 1 件ずつ読む。間隔はページ間隔と 3 秒の長い方で、並列にしない。Cookie は送らない。年齢制限の応答と年齢確認の URL からは本文、カテゴリ、タグを保存しない。429 / 503 では印を付けず、次回の続きから読む。中止は次の取得の前に効く。この段階で中止したら全取得を中止として返し、429 / 503 や通信の失敗で止めたら読み残しを `notice` で伝える。進捗の文言には残りの件数から終わるまでの目安を添える（`library_walk::detail_progress_line`）。保存先は `booth_category_id`、`booth_category_name`、`booth_category_parent`、`booth_tags`、`booth_detail_at`（DB版7）。省略されたカテゴリとタグは既存の値を消さない。

## ファイルのダウンロード

内蔵ブラウザが有効で、自動整理がオン、ライブラリフォルダがあるとき、未ダウンロードの行か「ダウンロード」を押すと、押したファイルだけを `https://booth.pm/downloadables/{番号}` から Rust の HTTP クライアントで取得する。WebView のセッションを使い、通常の取得でブラウザを移動・前面表示しない。番号は保存済みの `downloadable_id`、無いときは番号だけのファイル名。署名付きの別ホストへ移ったダウンロードも、押した1件だけ保存先を `ダウンロード/VRCLibMan/{商品ID}/{ファイル名}` にする。パス検査は拡張の自動整理と同じで、別の場所、別の商品ID、サブフォルダ、`..`、シンボリックリンクは拒否する。ダウンロードした中身が HTML のときは消し、窓を前面にしてログインを案内する。年齢確認の URL は開かず、通過もしない。ブラウザがオフのときはボタンを出さず、拡張の自動整理のままにする。ライブラリのフォルダか自動整理が足りないときは、押しても始めず（サイドバーに失敗を残さず）、設定の「ライブラリとダウンロード」へ移る操作付きの通知を出す（`downloads.ts` の `downloadBlocker`。判定の正本は Rust）。一括や自動のダウンロードはしない。押したファイルは `browser.rs` の `PARALLEL_DOWNLOADS`（3件）まで並行して受け取り、超えた分は順番待ちにする。受け取り中と順番待ちの間は、ページが始めたダウンロードの保存・全取得・タブの変更・アプリ更新の適用を止める。同じ商品フォルダへ並行して書くので、ステージングのファイルは `create_new` で作る。進捗は `booth-file-download`（`queued` / `receiving` と受信バイト数 / `moving` / `done` / `error`）だけで送り、上部の帯には出さずサイドバーの「ダウンロード」一覧に出す（[デザインガイド](design/README.md#ダウンロード)）。記録に商品名、ファイル名、クエリは残さない。`download_booth_file` は移した先の絶対パスを返し、完了の `booth-file-download`（phase `done`）にも `path` を載せる。画面は完了の通知とその行に「保存先を開く」を出す。完了した商品は、画面のリモート確認結果（`remoteProductProbe.ts` の60秒キャッシュ）を捨てて確認し直す。リモート確認結果を一覧へ重ねるときも、手元にある行は読み直した一覧の状態を正とする。

## 購入したファイルと無料配布のファイル

ファイル情報が 1 件もない商品のカードで、購入履歴に贈ったギフトでない注文として載っている商品（`ProductFlag.purchased`。ギフトかどうかは詳細にしか出ないので、詳細を読んだ注文か、本人がギフトの印を決めた注文だけを数える）には、内蔵ブラウザが有効なときだけ「購入したファイルを読み込む」を出し、「無料配布のファイルを探す」は出さない。押したときだけ上の購入完了のあとと同じ読み方（隠した子 WebView でライブラリを最大 3 ページ）でその商品のファイル行を加える（`fetch_purchased_files`）。見つからなければ何も保存せず、理由を `notice` で返す。それ以外の商品のカードには、内蔵ブラウザが有効で非公開でないときだけ「無料配布のファイルを探す」を出す（説明文は付けない。押しても本体はダウンロードせず、ファイル行を加えるだけなので、ダウンロードと取り違えない名前にする）。押したときだけ `fetch_free_files` が公開の `https://booth.pm/ja/items/{id}.json` を 1 回、Cookie なしで読む（`free_files.rs`。取得は `booth_detail.rs` と共用）。`status` が `free_download` のバリエーションのファイルだけを、`downloadable_id` 付きの未ダウンロード行（`product_files`）として既存の取り込みと同じ経路で加え、無料と年齢制限の印だけ更新する。名前、ショップ、説明、カテゴリ、タグは書かない。年齢制限の商品でも本文は保存しない。有料、年齢確認、404、429 / 503 は何も保存せず理由を返す。有料と一覧なしは失敗ではないので、エラーではなく `notice` で返し、画面は通常の通知で出す。確認できなかったとき（年齢確認、404、429 / 503、通信の失敗）だけをエラーにする。ダウンロード、購入、BOOTH のライブラリへの追加はしない。取得は上の「ダウンロード」を本人が 1 件ずつ押したときだけで、ログインや年齢確認の扱いも同じ。記録は ID の末尾 4 桁、HTTP の状態、件数だけ。

## Windows の窓の作り方と記録

Windows では、BOOTH の窓を同期コマンドの中で作らない。WebView2 は再入できず、IPC のコールバックから `WebviewWindowBuilder::build` すると新しい窓だけが応答しなくなる（メインの窓は動いたままに見える）。開く・ライブラリへ移動する・戻る進む・閉じるは async コマンドにし、コールバックが返ったあとメインスレッドで行う。データベースのロックを持ったまま窓を作らない。ページ読み取りの待ちも UI スレッドに載せない。`booth-browser` をメイン画面の `EBWebView` と同じ data_directory にしない。操作とページの移動先はアプリデータの `booth-browser.log` に残す。一般サイトのページ読み込みは origin だけを記録し、パス・クエリ・断片は残さない。閲覧データを削除するときは、この記録からも開いたサイトの行を消し、未対応カテゴリの行だけを残す（`log_without_visited_sites`）。BOOTH のインポートや巡回の記録は検証済みライブラリのパスまでとする。BOOTH / pixiv のログイン用別窓要求は元のタブで開き、ほかの http / https の別窓要求は新しいタブで開く。年齢確認を自動通過しない。

メイン画面にブラウザの子 WebView があると `get_webview_window("main")` は取得できないため、トレイ・深いリンク・単一起動からの再表示は `get_window("main")` で既存ウィンドウを取得する。

## ログイン状態と権限

内蔵ブラウザのログイン状態と、ほかのサイトに渡す権限は次のとおり守る（確認の範囲は [検証記録](verification.md#内蔵ブラウザのログイン状態と権限の見直し2026-11-20)）。

- ページ（`booth-tab-N`）からのカメラ・マイク・位置情報・通知・画面共有・MIDI・センサーの要求は `page_permission` で拒否する。応答を決めないと、macOS の wry はカメラとマイクを確認なしで許可するため。
- 確認用 WebView（`booth-probe`）はダウンロードを保存せず、新しい窓も開かない。機能をオフにして閉じるときは確認用も捨てる。
- 専用プロファイルのフォルダは `create_session_dir` で作り、Unix では所有者だけが読める 0700 にする。Linux では Cookie が平文で入るため。
- 設定の「内蔵ブラウザの閲覧データを削除」は、機能がオフでもプロファイルが残っていれば出す（`booth_session_stored`）。オフにしてもログイン状態は端末に残るため。
- 全取得と購入履歴の読み込みは、ページを読む前に、タブの本当のアドレスがページの申告と同じ BOOTH のホストであることを確かめる（`confirm_walk_page`）。アドレスを読めないときは止めない。
