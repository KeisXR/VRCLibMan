# Windows での確認と残りの実装

2026-11-17 のセキュリティ確認のうち、Linux のコンテナでは確かめられなかった分の引き継ぎです。Windows で作業するエージェント向けに書いています。先に [AGENTS.md](../AGENTS.md) を読んでください。終わった項目は結果を [検証記録](verification.md) に書き、この文書から消します。全部終わったらこの文書ごと消してください。

対象はブランチ `claude/epic-ptolemy-5c5d06`。Linux で確かめた範囲と方法は、検証記録の次の 2 件にあります。

- [内蔵ブラウザのタブから asset プロトコルで読める範囲](verification.md#内蔵ブラウザのタブから-asset-プロトコルで読める範囲2026-11-17)
- [残りの指摘への対応](verification.md#残りの指摘への対応自動整理の判定csp開く種類拡張の保存領域2026-11-17)

## 進め方の決まり

- 検証用のビルドは、インストール済みの VRCLibMan とデータフォルダ（`%APPDATA%\app.vrclibman.desktop`）・受信口（17321 番）を共有します。本人のライブラリを壊さないよう、検証記録の「アプリが前面にないときの通知（2026-11-16）」と同じく、ソースを一時フォルダへ写して識別子と受信口の番号を変えたビルドを使うか、インストール版を終了し、データフォルダを退避してから行います。
- 実際の BOOTH を使う確認は、本人のアカウントと本人の操作で行います。商品名、注文番号、ダウンロードの署名付き URL、ローカルのパスは記録に書きません。年齢制限の商品は使いません。購入、一括ダウンロードはしません。
- 失敗を見つけたら、原因を調べて直し、テストを足し、変更前後の結果を検証記録に書きます。直せないときは、分かったことだけを書いて止めます。
- コミットは依頼されたときだけ作ります（AGENTS.md）。

## 1. 確認だけのもの（コードは入っている）

### 1-1. `cargo test` と `npm test`

Windows でだけコンパイルされるコード（`#[cfg(windows)]`）があります。Linux では `cargo test` 549 件、`npm test` 全件が成功しています。Windows でも両方を通してください。

### 1-2. asset プロトコルの範囲（最優先）

`tauri.conf.json` の asset の範囲を、データフォルダ全体から `thumbs`・`previews`・`hero_images` に絞りました。Windows の実アプリで次が今までどおり表示されることを見ます。

| 見る場所 | 読むフォルダ |
| --- | --- |
| アバター・アセット・ワールドの商品カードのサムネイル（インポート画面の「サムネイルを保存」のあと） | `thumbs` |
| アセット画面で商品を選んだときの右パネル「プレビュー」の大きい画像 | `previews` |
| アバター詳細のヒーロー画像（自分で設定した画像） | `hero_images` |

表示されないものがあれば、その画像のパスがどのフォルダにあるかを調べます。3 つのフォルダの外に保存している画像があったら、範囲を広げるのではなく、保存先をこの 3 つのどれかにそろえる方向で直します（範囲に `library.sqlite` を入れないため）。

余力があれば、WebView2 でも外部ページから読めなくなったことを確かめます。内蔵ブラウザで `http://127.0.0.1:<番号>/` のテストページを開き、そのページから `fetch("http://asset.localhost/" + encodeURIComponent("C:\\Users\\<名前>\\AppData\\Roaming\\<識別子>\\library.sqlite"))` が 403 になること、`thumbs` の中の画像は読めることを見ます。変更前（`43ccfa9`）で同じページが `library.sqlite` を読めたかどうかも分かれば書いてください。Linux の再現アプリでは読めましたが、WebView2 では未確認です。

### 1-3. メイン画面の CSP

`tauri.conf.json` に `csp` を入れました。設定を誤ると、画像が出ない、操作が効かない、画面が白い、といった形で壊れます。Windows は IPC に `http://ipc.localhost`、asset に `http://asset.localhost` を使うので、Linux の結果をそのまま当てはめられません。

デバッグビルドは開発者ツールを開けます（右クリック →「検証」、または Ctrl+Shift+I）。Console に `Refused to …` と `Content Security Policy` を含む行が出ていないかを見ます。

```powershell
npm ci
npm run build
cd src-tauri
cargo build --features tauri/custom-protocol
.\target\debug\tauri-app.exe
```

次を一通り操作し、どこでも Console に CSP の行が出ないこと、見た目が今までと同じことを確かめます。

- 初回セットアップの全画面、使い方ガイド
- アバター一覧、アバター詳細（ヒーロー画像の設定と解除、商品カード、「分類を編集」のダイアログ）
- アセット、ワールド（ジャンル列の開閉、ドラッグでのジャンル移動、右パネルのプレビュー・ファイルのタブ）
- 検索、購入履歴、ログ、インポート（JSON のドラッグ＆ドロップを含む）、設定（全カテゴリ、対応表エディタ、「更新を確認」、データの書き出し）
- サイドバーのアカウント表示（BOOTH のアイコン画像が出る。`pximg.net` か `booth.pm` 以外から来ていたら Console に出る）
- サムネイルを保存していない商品のカード（BOOTH の画像サーバーから直接出る）
- 内蔵ブラウザ：右パネルのタブとアドレスバー、ブックマーク、「別ウィンドウで開く」のタブ列と操作バー（操作バーもアプリのページなので同じ CSP が掛かる）
- 通知欄、ダウンロード一覧、「Unityで開く」のダイアログ

CSP の行が出たら、止められた種類（`img-src` など）と相手（ホストまで。パスとクエリは書かない）を記録します。アプリが実際に必要としているものなら、`tauri.conf.json` の `csp`、`src/media.ts` の `remoteImageUrl`（画像のとき）、`test/media.test.mjs` をそろえて直します。`script-src` に `'unsafe-inline'`・`'unsafe-eval'` を足す、`img-src` や `connect-src` に `https:` や `*` を足す、という直し方はしません。

`npm run tauri dev`（Vite の開発サーバー）でも画面が出ることを一度見てください。Linux（WebKitGTK）では、開発サーバーにつないだデバッグビルドで起動直後の画面が出ました。Windows で壊れる場合は、`tauri.conf.json` の `devCsp` で開発時だけ緩めます。

### 1-4. 拡張の自動整理（本人がよく使う機能。慎重に）

`extension/download-route.js` の、クリックの記録が無いときの予備の判定だけを絞りました。クリックの記録で振り分ける経路（「取得」「LibMan で取得」、元のリンクのクリック）には手を入れていません。Linux では、本物の拡張を Chromium に読み込み、BOOTH の役をするローカルサーバーで変更前と変更後を比べ、ふだんの 10 通りが一致しました。実際の BOOTH では確かめていません。

Chrome か Edge に、このブランチの `extension` フォルダを読み込み（アプリの設定から用意されるフォルダでもよい）、「ダウンロードを自動整理」をオン、ライブラリフォルダを設定した状態で、本人のふだんの手順を一通り行います。

1. 購入ライブラリで「LibMan で取得」
2. 商品ページのポップアップ「このページのファイル」の「取得」
3. 購入ライブラリで、BOOTH の元のダウンロードリンクを押す
4. 商品ページ（`booth.pm/ja/items/…` と `<ショップ>.booth.pm/items/…` の両方）で、元のダウンロードリンクを押す
5. 注文詳細（`accounts.booth.pm/orders/…`）とギフト・無料ダウンロードの一覧で、元のリンクを押す

それぞれ、ファイルが `Downloads\VRCLibMan\<商品ID>\` を通ってライブラリの `<商品ID>` フォルダへ入り、商品カードに「ローカル」と出ることを見ます。同じ操作を v0.9.0（`43ccfa9` の拡張）でも行い、違いが無いことを確かめます。変更前に振り分けられていて、変更後に振り分けられなくなった経路があれば、それが今回の不具合です。

あわせて、実際の値の形を記録してください。拡張のサービスワーカーのコンソール（`chrome://extensions` →「Service Worker」）で、ダウンロードの直後に次を実行します。

```js
(await chrome.downloads.search({ orderBy: ["-startTime"], limit: 1 })).map(({ url, finalUrl, referrer }) => ({
  url: url.split("?")[0],
  finalHost: new URL(finalUrl).host,
  finalPathShape: new URL(finalUrl).pathname.replace(/[0-9a-f-]{8,}/gi, "<id>").replace(/\d+/g, "<n>"),
  referrer: referrer.split("?")[0],
}))
```

知りたいのは次の 3 点です。署名やファイル名は記録に書きません。

- `url` は必ず `https://booth.pm/downloadables/<番号>` か
- `referrer` はページの先頭（`https://booth.pm/` など）だけか、ページの URL 全体か
- 転送先のパスに `/items/<商品ID>/` や `/downloads/<番号>/` が含まれるか

`url` が必ず `downloadables` なら、予備の判定をさらに絞れます（いまは BOOTH のアドレスならどれでも始まりとして認めています）。絞るかどうかは本人に確認してください。

### 1-5. 拡張の保存領域

`background.js` が `chrome.storage.local` を拡張自身のページだけに限るようにしました（`TRUSTED_CONTEXTS`）。BOOTH のページ内で動く部品はこの領域を使っていません。拡張を読み込み直したあと、次が今までどおり動くことを見ます。

- ポップアップ、サイドパネル、設定ページが開き、ペアリングコードと設定が残っている
- 「すべて読み込む」「新しい購入を送る」「購入履歴を読み込む」（offscreen 文書が動く）
- BOOTH 上の印（登録済み・保存記録あり）、「LibMan に登録」、絞り込み
- アプリを止めた状態でファイルを取得し、アプリを起動すると未送信の通知が送られる
- 購入完了ページの自動登録（実際に購入する機会があれば。無ければ未確認と書く）

### 1-6. プログラムを直接開かない

`open_local_path` は、開くと実行される種類（`.exe`・`.bat`・`.lnk` など。`library_files.rs` の `RUNS_WHEN_OPENED`）を既定のアプリへ渡さず、エクスプローラーで保存先を示します。

中身が `echo test` だけの `test.bat` を、検証用ビルドのライブラリへ登録して確かめます。登録は、検証記録の通知の確認と同じく、`Downloads\VRCLibMan\<商品ID>\test.bat` に置いて `/download-finished` を公式拡張の Origin とペアリングコード付きで送ります。

- 商品カードの「ファイル test.bat」を押す → コマンドプロンプトが出ない。エクスプローラーがそのファイルを選んだ状態で開き、「プログラムやショートカットは、ここからは開きません。保存先のフォルダを開きました」と出る
- 同じ商品の zip や unitypackage は今までどおり開く。フォルダも開く

### 1-7. `/download-finished` のパス

`extension_delivery::recovered` が、受け取ったパスの文字を先に確かめるようになりました。ふだんの流れが変わっていないことを見ます。

- 拡張で取得 → ライブラリへ移る（1-4 で見る）
- アプリを止めたまま取得 → アプリを起動（起動時の回収でファイルが移る）→ そのあと拡張の通知が届く → 二重に登録されず、サイドパネルの表示が「ライブラリに移しました」になる

これは GitHub 上で本人が行います。Actions の release を「Run workflow」で試し、4 つのターゲットがすべて成功することを確かめます（外部 Action をコミットで固定したため。[配布とアプリ内更新](updater.md#外部-action-の固定)）。

## 2. 実装から行うもの

### 2-1. 「ネットから取得した」の印を付ける・残す

Windows は、ブラウザで落としたファイルに `Zone.Identifier` という別ストリームで印を付け、中のプログラムを実行するときに警告を出します。いまのアプリでは、この印が付かない・消える経路があります。

| 経路 | いま | 場所 |
| --- | --- | --- |
| 内蔵ブラウザの「ダウンロード」（Rust の HTTP クライアントで受け取る） | 印が付かない | `quiet.rs` の `fetch_staged_file` |
| 拡張で受け取ったファイルを、別のドライブのライブラリへ移す | コピーになり、印が消える | `library_files.rs` の `claim_by_copy` |
| ページが始めたダウンロードの登録（内蔵ブラウザ） | 要確認（WebView2 が印を付けるか、移動で残るか） | `browser_auto.rs` の配置 |
| 手動の「リモートへコピー」「ローカルへコピー」、自動同期 | 要確認 | `library_files.rs` のコピー |

やること：

1. まず現状を記録します。それぞれの経路でファイルを 1 件受け取り、PowerShell で印を見ます。同じドライブと別のドライブ（ライブラリを別ドライブに置く）の両方で行います。

   ```powershell
   Get-Item -LiteralPath <ファイル> -Stream * | Select-Object Stream, Length
   Get-Content -LiteralPath <ファイル> -Stream Zone.Identifier
   ```

2. `library_files.rs` に、Windows でだけ働く 2 つの関数を足します。どちらも失敗は無視します（FAT / exFAT や一部の共有は別ストリームを持てないため）。
   - 印を付ける：`<パス>:Zone.Identifier` に `[ZoneTransfer]\r\nZoneId=3\r\n` を書く。`HostUrl` と `ReferrerUrl` は書かない（署名付き URL を残さない契約のため）。
   - 印を写す：コピー元に `Zone.Identifier` があれば、コピー先へ同じ中身を書く。
3. 受け取りが終わった直後（ステージングのファイルを閉じたあと、ライブラリへ移す前）に印を付け、別ドライブへのコピーでは印を写します。同じドライブの移動（`MoveFileExW`）は印が残るはずなので、1 の記録で確かめます。
4. テスト：`#[cfg(windows)]` で、一時フォルダのファイルに印を付けて読み戻す、印のあるファイルと無いファイルをコピーして結果を見る。Windows 以外では何もしないことも 1 件。
5. 実機：受け取った zip をエクスプローラーで展開し、中に置いた試験用の `.exe`（無害なもの）を実行すると SmartScreen か「発行元を確認できません」の確認が出ること。プロパティに「ブロックの解除」が出ること。
6. 今までの動きが変わらないこと：「Unityで開く」（zip からの取り出しと unitypackage の受け渡し）、ファイル名突合、リモートへの自動同期（NAS や Nextcloud のフォルダへコピーできる）、同名ファイルの番号付け。
7. AGENTS.md の「ライブラリへの配置」の項に、守ることと理由を 1〜2 文で足し、検証記録を書きます。

macOS の隔離属性（`com.apple.quarantine`）は別の作業です。Mac の実機が無いなら入れず、未対応と書いてください。

## 3. 見送ったもの（作業しない）

- **ペアリングコードの送り方**：拡張は、アプリが起動しているかを確かめるたびに 17321 番へコードを送ります。アプリが止まっている間に別のプログラムがその番号で待つとコードを受け取れますが、そのプログラムは同じ PC で動いており、同じユーザーならデータフォルダを直接読めます。コードを送らずに確かめる方式へ変えるには、拡張とアプリの両方の通信と、古い版との互換の扱いが要るので、今回は見送りました。
- **開発用の依存**：`picomatch` の既知の問題（GHSA-fc5q-39xc-vjpf）は最新版まで対象で、直った版がありません。配布物には入りません。直った版が出たら `npm update` で上げます。
