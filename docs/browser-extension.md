# 普段のブラウザで使う（拡張 v0.1.17）

普段のChrome / EdgeのBOOTHログインで、選んだ1件のファイルを取得し、VRCLibManへ整理できます。BOOTHの商品カードには、アプリで確認できる所持・保存記録と対応アバターも表示します。

## 導入と取得

1. この変更を含むアプリと拡張を両方更新します。拡張だけの更新では状態表示は使えません。
2. アプリを起動し、拡張へペアリングコードを保存します。アプリでライブラリフォルダを指定し、拡張の「ダウンロードしたファイルを自動整理する」をオンにします。
3. 普段のブラウザでBOOTHにログインし、対象の商品ページかライブラリを開きます。
4. BOOTHのダウンロード欄を表示して、拡張アイコンを押します。「このページのファイルを取得」にある、必要なバリエーション・ファイルのボタンを1件だけ押します。
5. ブラウザで取得が始まり、完了すると商品情報と保存完了がアプリへ届きます。アプリを閉じていた場合、通知をブラウザ内に保持します。アプリ起動後、約1分ごとの確認か「接続して再送する」で再送します。ブラウザ終了中は再送しません。

対象は `zip` / `unitypackage` / `rar` / `7z` / `vrm`。今見えるページのファイルIDから商品とバリエーションが一意に分かるものだけを、ポップアップに表示します。ポップアップの一覧は、ページ表示後に開き直すと更新します。ページが変わった場合も開始直前に再照合します。一括取得や失敗後の自動再ダウンロードはしません。

BOOTHの元のダウンロードリンクも利用できます。元のクリックやページ移動は変更せず、確認できたクリックとファイルIDの対応を記録します。クリックの記録が間に合わない経路や、商品・バリエーションが曖昧なものには推測で対応を付けません。正確な照合が必要な場合は拡張のファイルボタンを使ってください。

保存前は `Downloads/VRCLibMan/<商品ID>/` を経由します。同名はブラウザが別名を付け、元のファイルを上書きしません。照合済みファイルは、別名になっても元のファイルIDとバリエーションの行へ保存記録を付けます。アプリ側のパス・商品ID・シンボリックリンクの検査は維持します。

## BOOTH上での表示

### ダウンロードから分類する

ペアリング済みの拡張では、BOOTHのダウンロードリンクを押すと `vrclibman://import` でアプリを開き、選んだ商品の情報を送って「取得した商品の分類」を表示します。元のダウンロードはBOOTHとブラウザがそのまま処理します。ダウンロード欄に追加される「LibManでインポート」からは、ファイルを再取得せずに同じ商品の取り込みを行えます。今見えているページから商品とファイルIDを一意に照合できる場合だけ取り込みます。

商品情報だけの取り込みは、自動整理や内蔵ブラウザがオフでも使えます。ファイルの移動・保存完了の記録には、従来どおり自動整理とライブラリフォルダの設定が必要です。アプリと拡張を両方更新し、開いていたBOOTHページも再読み込みしてください。ブラウザが外部アプリの起動確認を出した場合は、その画面で起動を許可してください。macOSではアプリを `/Applications` に置く必要があります。

ポップアップの「対応アバター」には、保存した商品ページのタイトルと説明の対応欄を読み、対応表で名前・別名を確認できたアバターを自動入力します。共通素体の別アバターを推測で追加することはありません。マウスを重ねると出る「×」で外せます。キーボードのフォーカス時とタッチ端末でも削除できます。名前・別名で検索して手動追加し、「分類を確定」で分類先とまとめて保存します。対応表にない名前は表示だけに留めます。この読み取りはRustの既存規則で行い、AIや外部APIへの問い合わせは行いません。内蔵ブラウザからの分類にも同じ入力欄を使います。

「後で分類する」は登録と分類待ちを残します。同じ商品の「LibManでインポート」を再度押した場合も、その商品を先頭にして再開します。分類確定済みの商品は、再ダウンロードでも再確認せず手動分類を維持します。

起動用URLには商品本文・パス・ペアリングコードを入れません。商品情報はOrigin固定とBearer認証を通る `POST /import-download` へ1件だけ送ります。起動待ちでは読み取りの `/health` だけを確認し、インポートの応答が不明な場合に自動再送はしません。ページのリンク横に失敗理由を出すので、アプリの登録状態を確認してから必要に応じて押し直してください。

- **登録済み（所持未確認）**：商品情報がアプリにあるだけで、購入を断定しません。
- **所持確認済み**：取り込み済みバリエーションに所持の記録があります。有料購入の証明という意味ではありません。
- **保存記録あり**：ファイルとの結び付けがアプリにあります。取得後に外部で削除・移動された可能性があり、現時点のファイル存在を保証しません。
- **保存記録なし／ファイル情報未取得**：保存やファイル情報をまだ確認できていません。
- **未登録**：この接続先アプリの管理対象にありません。除外商品も表示対象外です。

対応アバターは、アプリに登録された所持アバターとの対応だけを表示します。共通素体からの表示は「共通素体」を付け、髪には適用しません。未登録商品の説明を新たに巡回・分類する機能はありません。絞り込みは表示中の対応情報を使い、未登録・対応未確認の商品は残します。一般対応・非対応の断定には使わないでください。

「状態を更新」かブラウザへのフォーカス復帰で最新のアプリ情報を照会します。検索結果の追加読み込みにも追従します。アプリに接続できないときは絞り込みを解除し、接続の案内を出します。

## 保存・通信と復旧

Cookieやパスワードは読み出さず、アプリにも送りません。ファイル取得はブラウザ自身のセッションを使います。ページの表示情報はローカルHTTPの認証済み受信口へ照会します。ページへローカルパスやペアリングコードは表示しません。

取得を追跡する商品情報・ファイルID・バリエーション、未送信通知の保存パスなどを `chrome.storage.local` に保持します。成功した通知と対応情報は削除します。接続先の異なる通知は保留し、元の接続に戻すまで送信しません。通知の受信記録はアプリに最近2000件を保持します。アプリ起動時に先にファイルが回収された場合に備え、保存元・移動先・商品ID・移動日時の対応も最近2000件をアプリ内に保持します。通知の取得開始日時と商品・サイズ・保存記録が一致したときだけ照合します。拡張の削除で未送信通知は消えますが、保存済みファイルは残ります。

ログイン画面など、HTMLとして取得されたものは登録せず、ポップアップに理由を出します。取得が中断した場合はブラウザのダウンロード画面を確認し、必要ならその画面で再開してください。アプリの自動整理がオフ、フォルダ未設定、除外、パス検査失敗なども通知を保留し、ポップアップにエラーを出します。

## 確認範囲

合成データのWorkerテスト、SQLiteテスト、Chromiumでの表示・絞り込み・クリック確認を用意しています。実BOOTHのログイン、認証リダイレクト、期限付きURL、Chrome/Edgeの実拡張としての取得、Windows/macOSでのファイル移動は別途確認が必要です。

先行ツールからコードや素材を取り込んでいません。外部コードを新たに採用する際は、明示されたライセンスと利用条件を先に確認します。
