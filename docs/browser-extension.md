# 普段のブラウザで使う（Chrome / Edge 拡張）

VRCLibMan の拡張機能は、普段の Chrome / Edge の BOOTH ログインのまま、商品情報・購入履歴・購入完了を同じ PC の VRCLibMan へ送ります。BOOTH の商品カードには、アプリにある所持・保存記録と対応アバターを表示します。サイドパネルには、アプリに登録済みの商品をアバターとジャンルで並べます。拡張の版はアプリの版と同じ番号です。

## 導入と接続

アプリは拡張機能を同梱していて、決まったフォルダへ用意します。このフォルダをブラウザに一度読み込ませると、以後はアプリの更新に合わせて拡張機能も新しくなります。

1. アプリの「設定 → BOOTH → BOOTH の読み込み方」で「変更」を押し、「拡張機能」か「両方」を選びます。「拡張機能をつなぐ」に、拡張機能のフォルダのパスが出ます（Windows は `%LOCALAPPDATA%\app.vrclibman.desktop\browser-extension`）。まだ無いときは「拡張機能を用意する」を押します。
2. 「パスをコピー」を押します。
3. Chrome は `chrome://extensions`、Edge は `edge://extensions` を開き、デベロッパーモードをオンにします。以前に zip から読み込んだ VRCLibMan の拡張機能があれば「削除」します。
4. 「パッケージ化されていない拡張機能を読み込む」を押し、フォルダを選ぶ画面のアドレス欄にコピーしたパスを貼り付けて、そのフォルダを選びます。
5. 拡張のアイコンを押し、ポップアップの「アプリとつなぐ」にペアリングコードを貼って「接続する」を押します。見出しの印が「接続中」になれば完了です。

拡張機能の ID は、どのフォルダから読み込んでも同じです。zip から読み込んだ拡張機能からこのフォルダへ移しても、ペアリングコードを作り直す必要はありません。

### 更新

アプリを更新すると、起動時にフォルダの中身が同じ版に置き換わります。拡張機能は約 10 分ごと（とブラウザの起動時）にアプリへ版を問い合わせ、新しい版があれば自分で読み込み直します。読み込みの実行中は終わるまで待ちます。ポップアップを開いたときに新しい版があれば「拡張機能を v… に更新できます」と「更新する」も出ます。更新すると、開いている BOOTH のページの表示は古いままになるので、ページを再読み込みしてください。

読み込み直しても版が変わらないときは、拡張機能が別のフォルダ（zip を展開した場所など）から読み込まれています。ポップアップの案内に従って、アプリのフォルダから読み込み直してください。フォルダを移動・削除すると、ブラウザは拡張機能を読み込めなくなります。

zip から入れた拡張機能も使えますが、自動では新しくなりません。アプリと拡張は同じ版にそろえて使います。

## 画面

### ポップアップ

見出しに接続の状態（接続中・未接続・アプリ未起動・待機中）を出し、その下に今開いているページでできる操作を 1 つだけ出します。

| 開いているページ | 主な操作 | ほかの操作 |
| --- | --- | --- |
| 商品ページ | この商品を送る | アプリで開く（登録済みの商品）、このページのファイルを 1 件ずつ取得 |
| 購入ライブラリ・ギフト・無料ダウンロード | 新しい購入を送る | すべて読み込む、購入履歴を読み込む |
| 購入履歴・注文詳細 | 購入履歴を読み込む | 購入ライブラリを開く |
| ほかのページ | 購入ライブラリを開く | |

拡張機能を入れる前や更新する前に開いた商品ページでは、ページを読めないので、そのことと「ページを再読み込み」を出します。

読み込みの実行中は、件数とページ数、中止、「サイドパネルで見る」を出します。ポップアップを閉じても読み込みは続きます。下の段には「ダウンロードを自動整理」と、アプリへの未送信の件数があります。アプリが起動していないときに送ると、拡張がアプリの起動を試みます。

### サイドパネル

ポップアップの「サイドパネルを開く」か「未送信 N 件」で開きます。サイドパネルに対応しないブラウザでは、同じ画面をタブで開きます。上の「ライブラリ」「記録」で表示を切り替えます。「未送信 N 件」から開くと「記録」が出ます。

**ライブラリ**

- **開いているページ**：見ているタブに合わせて変わります。商品ページでは、登録・所持・保存記録と対応する所持アバター、購入の記録、「この商品を送る」、「アプリで開く」、このページのファイルの「取得」を出します。購入ライブラリでは、このページの商品の件数とアプリに未登録の件数、「新しい購入を送る」「すべて読み込む」「購入履歴を読み込む」を出します。購入履歴では「購入履歴を読み込む」を出します。BOOTH 以外のページでは出しません。
- **購入の記録**：見ている商品の、いちばん新しい注文の日付、贈ったギフトかどうか、ほかの注文の件数、「注文を開く」（BOOTH の注文詳細）、購入した対応版です。金額は出しません。購入履歴を一度も読み込んでいないときは、登録済みの商品にだけ「購入履歴を読み込むと、ここに購入日が出ます」と出します。記録が無いことを未購入とは書きません（無料の商品やもらったギフトがあるため）。
- **ライブラリ**：アプリに登録済みの商品を、アバターとジャンルで並べます。上の並びからアバター、「すべて」（アセット）、「ワールド」を選びます。アバターを選ぶと、アプリのアバター詳細と同じく「アバター本体」、ジャンルごとの対応アイテム（共通素体からのものは「共通素体」）、「汎用」、「対応版未設定」が並びます。「すべて」と「ワールド」は、アプリのアセット・ワールドの一覧と同じジャンルで、見出しだけを先に出します。見出しを開くと 30 件ずつ出します。名前とショップで絞り込めます。
- **見ているページのアバター**：商品ページを見ているとき、その商品に対応する所持アバターを並びの先頭に出して「このページ」と付け、先頭の 1 体を選びます（直接の対応が先、共通素体からの対応が後）。選び直すのは見ている商品が変わったときだけで、自分で別のアバターを選んだあとは、同じ商品を見ているあいだ変えません。設定の「見ている商品の対応アバターを先頭に出して選ぶ」でオフにできます。
- **商品を押したとき**：BOOTH を見ているタブでは、そのタブでその商品のページへ移ります。BOOTH 以外のページを見ているときは新しいタブで開きます。Ctrl / ⌘ / Shift を押しながら、または中クリックでは、今のタブを動かさずに後ろのタブで開きます。

- **アプリで開く**：アプリに登録済みの商品のカードと、保存記録のあるファイルの行に出します（ポップアップも同じ）。押すと、アプリのメイン画面がその商品の場所へ移り、ウィンドウが前に出ます。アセットとワールドは一覧の中のその商品、アバター本体はそのアバターの画面です。常駐中でウィンドウが無いときは作り直します。まだ分類されていない商品は開けず、理由を出します。Windows は、ほかのアプリが前面にあるとウィンドウを前に出さずタスクバーを点滅させることがあります。そのときはタスクバーの VRCLibMan を押してください。アプリが起動していないときは起動せず、接続できないことを出します。

並べ方と分け方はアプリが決めます（アプリの画面と同じ規則）。除外した商品は出しません。サムネイルは、アプリが保存している画像をアプリから受け取ります。BOOTH の画像サーバーへは通信しません。年齢制限の商品も、ほかの商品と同じに名前と画像を出し、「R-18」を付けます。アプリが起動していないときは一覧を出さず、古い一覧も残しません。一覧は、パネルを開いたとき、取り込みやダウンロードが終わったとき、1 分以上たってブラウザへ戻ったとき、「ライブラリを読み直す」を押したときに読み直します。

**記録**

- **ダウンロード**：拡張が追跡している取得の進み具合と、アプリへ知らせた結果（最近 10 件）。
- **アプリへ未送信**：アプリが止まっていたなどで届いていない、ダウンロードしたファイルと購入完了。「アプリへ送り直す」で送ります。約 1 分ごとにも自動で送り直します。
- **最近の取り込み**：直近の取り込みの日時と件数。ライブラリを最後まで読めたものには「完了」を付けます。

取得中のファイルと未送信があるときは、「記録」に件数を添えます。

**実行中**（読み込みの進み具合と中止）は、どちらの表示でも上に出します。止まった・中止したときは理由を「最後の読み込み」に残します。

### 設定

ポップアップの設定ボタンで開きます。変更はその場で保存します。

| 項目 | 既定 | 内容 |
| --- | --- | --- |
| ペアリングコード | なし | 状態と最後の通信日時も出します |
| BOOTH へのアクセス間隔 | 1.0 秒 | 0.5 秒、0.25 秒（確認あり）も選べます |
| 購入完了ページを自動で登録する | オン | 下の「購入履歴と購入完了」 |
| ダウンロードを自動整理 | オフ | アプリの設定と同じ値です |
| 商品に所持と対応アバターを表示する | オン | 下の「BOOTH 上での表示」 |
| 見ている商品の対応アバターを先頭に出して選ぶ | オン | サイドパネルのライブラリ。上の「サイドパネル」 |
| 診断情報をコピー | | 最後に使った BOOTH のタブの、ページの形だけを調べます。商品名やファイル名は含めません |

## 商品情報を読み込む

- **この商品を送る**：開いている商品ページを 1 件送ります。説明が短いときは、公開ページを Cookie なしで読んで補います。
- **すべて読み込む**：購入ライブラリ、ギフト、無料ダウンロードを順に 1 ページずつ読みます。3 つとも最後まで読めたときは、アプリがその一覧を「完全な一覧」として扱い、BOOTH から外れたファイルを「以前のファイル」にまとめます。
- **新しい購入を送る**：各一覧で登録済みの商品に出会うまで読みます。古い未登録商品の読み直しや、既存商品の説明・ファイル情報の更新には「すべて読み込む」を使ってください。

一覧を読んだあと、説明が短い商品は公開の商品ページを、BOOTH のカテゴリが無い商品は公開の JSON を、Cookie なしで 1 件ずつ読みます。カテゴリとタグは商品ページの HTML には入っていない（ページのスクリプトが埋める）ため、分類に使うカテゴリはこの JSON から取ります。年齢制限の商品は読みません。

読み込みは設定した間隔で 1 件ずつ行い、並列にしません。BOOTH からアクセス制限を受けたら指定された時間（60 秒まで）待って 1 回だけ再試行し、続くときはそこまでを送って止めます。ログイン画面へ転送されたら止めます。中止しても、読んだところまでは送ります。

アプリへ送れないときは、アプリの起動を試みてから 1 回だけ送り直します。それでも届かないときと、ペアリングしていないときは JSON を保存します。保存した JSON はアプリのインポート画面へドロップできます。

## 購入履歴と購入完了

「購入履歴を読み込む」は、購入履歴（`https://accounts.booth.pm/orders`）を 1 ページずつ読み、そのあとアプリがまだ詳細を持っていない注文を 1 件ずつ読みます。順序と止まり方は内蔵ブラウザと同じで、一度最後まで読んだあとは、新しい注文の無いページで一覧を止めます。読み込みにはアプリとの接続が必要です。ページから読む値と保存する値は [購入履歴](purchase-history.md) と同じです。

設定の「購入完了ページを自動で登録する」がオンのとき、本人が開いた購入完了ページ（`https://checkout.booth.pm/orders/<番号>`）から、その注文の専用データにある商品 ID・商品名・ショップ名だけを読みます。アプリはその商品を「取得した商品の分類」の待ちに入れ、注文を購入履歴に記録します。続けて拡張がその注文の詳細を 1 回だけ読み、日時と金額を埋めます。アプリが起動していないときは未送信として残し、起動後に送ります。購入完了のためにアプリを起動することはありません。同じ注文は 1 回だけ送ります。

同じ設定がオンのとき、本人が開いた購入履歴と注文詳細のページも、そのページだけをアプリへ送ります。アプリが起動していないときは送らず、残しもしません。

## ファイルを取得する

「ダウンロードを自動整理」をオンにし、アプリでライブラリフォルダを設定すると、次の 2 か所から 1 件ずつ取得できます。

- 商品ページを開いたポップアップの「このページのファイル」の「取得」
- BOOTH のダウンロード欄に足される「LibMan で取得」

どちらも、今見えているページのファイル ID から商品とバリエーションが一意に分かるもの（`zip` / `unitypackage` / `rar` / `7z` / `vrm`）だけが対象です。取得はブラウザ自身がログインのまま行い、`Downloads/VRCLibMan/<商品ID>/` を経由してアプリがライブラリへ移します。保存記録のあるファイルには、ポップアップとサイドパネルでは「取得」の代わりに「アプリで開く」を、BOOTH のダウンロード欄ではボタンの代わりに「保存記録あり」を出します。一括取得や失敗後の自動再ダウンロードはしません。取得が中断したときは、ブラウザのダウンロード画面で再開してください。

BOOTH の元のダウンロードリンクも使えます。元のクリックやページ移動は変更せず、確認できたクリックとファイル ID の対応を記録します。クリックの記録が間に合わない経路や、商品・バリエーションが曖昧なものには推測で対応を付けません。

ログイン画面など、HTML として取得されたものは登録せず、理由をサイドパネルの「記録」に出します。アプリの自動整理がオフ、フォルダ未設定、除外、パス検査の失敗も、通知を保留して理由を出します。

### 記録が無いダウンロードの振り分け

どの商品のファイルかは、クリックの記録で決めます。「取得」「LibMan で取得」と、確認できた元のダウンロードリンクのクリックがこれに当たります。

記録が無いダウンロードは、次の両方を満たすときだけ `Downloads/VRCLibMan/<商品ID>/` へ振り分けます。満たさないものは、ブラウザのふだんの保存先にそのまま保存されます。

- ダウンロードが BOOTH のアドレス（`https://booth.pm/downloadables/<番号>` など）から始まっている。BOOTH のページに置かれたリンクでも、別のサイトのファイルは対象にしません。
- 商品 ID が、BOOTH のアドレスのパス（`/items/<ID>` など）にある。見るのは、ダウンロードの始まりのアドレス、BOOTH が転送した先のアドレス、リンク元の BOOTH のページの 3 つです。`?` 以降と、BOOTH 以外のページの URL は見ません。

BOOTH は署名付きの別のサーバーへ転送します。別のサーバーへ転送されたダウンロードでは、Chromium が記録するリンク元はページの先頭（`https://booth.pm/` など）だけになりました（BOOTH 役のサーバーでの確認。[検証記録](verification.md#残りの指摘への対応自動整理の判定csp開く種類拡張の保存領域2026-11-17)）。その場合、この予備の判定で振り分けられるのは、転送先のアドレスに商品 ID が入っているときに限られます。

### ダウンロードから分類する

ペアリング済みの拡張では、BOOTH のダウンロードリンクを押すと、選んだ商品の情報をアプリへ送って「取得した商品の分類」を表示します。アプリが起動していないときだけ `vrclibman://import` でアプリを開きます。元のダウンロードは BOOTH とブラウザがそのまま処理します。ブラウザが外部アプリの起動確認を出した場合は、その画面で起動を許可してください。macOS ではアプリを `/Applications` に置く必要があります。

購入ライブラリでアプリに未登録の商品には「LibMan に登録」を出します。押すと、ファイルを取得せずにその商品だけを取り込み、分類を表示します。

商品情報だけの取り込みは、自動整理や内蔵ブラウザがオフでも使えます。ファイルの移動・保存完了の記録には、自動整理とライブラリフォルダの設定が必要です。

分類画面の「対応アバター」には、保存した商品ページのタイトルと説明の対応欄を読み、対応表で名前・別名を確認できたアバターを自動入力します。共通素体の別アバターを推測で追加することはありません。マウスを重ねると出る「×」で外せます。キーボードのフォーカス時とタッチ端末でも削除できます。名前・別名で検索して手動追加し、「分類を確定」で分類先とまとめて保存します。対応表にない名前は表示だけに留めます。この読み取りは Rust の既存規則で行い、AI や外部 API への問い合わせは行いません。

「後で分類する」は登録と分類待ちを残します。分類確定済みの商品は、再ダウンロードでも再確認せず手動分類を維持します。

起動用 URL には商品本文・パス・ペアリングコードを入れません。商品情報は Origin 固定と Bearer 認証を通る `POST /import-download` へ 1 件だけ送ります。起動待ちでは読み取りの `/health` だけを確認し、インポートの応答が不明な場合に自動再送はしません。ページのリンク横に失敗理由を出すので、アプリの登録状態を確認してから必要に応じて押し直してください。

### アプリが前面にないときの通知

アプリのウィンドウがどれも前面にないとき（別のアプリを使っている、最小化している、常駐でトレイだけになっている）に、ブラウザから届いたものを OS の通知で知らせます。対象は次の 3 つです。

- 拡張がファイルをライブラリへ移したとき（「ファイルを追加しました」）。1 件なら商品名を出し、年齢制限の商品は名前を出さず件数だけにします。
- 拡張から商品情報を受け取り、追加か更新があったとき（「商品を読み込みました」）。変化のない商品は数えません。
- 「取得した商品の分類」が必要になったとき。ダウンロードから届いた 1 件、拡張と内蔵ブラウザの購入完了が対象です（「取得した商品の分類を選んでください」）。

分類が必要なときも、前面にないあいだはウィンドウを前に出しません。以前はウィンドウを前に出していましたが、Windows はバックグラウンドのアプリが前面に出ることを制限するため、タスクバーが点滅するだけで気づけないことがありました。通知をクリックするとウィンドウが開き（常駐中は作り直し）、分類の画面が出ます。アプリのどれかのウィンドウが前面にあるときは通知を出さず、これまでどおりメイン画面を前に出して画面内で知らせます。

続けて届いたもの（未送信だった通知の送り直しなど）は 2.5 秒ためて 1 通にまとめます。そのあいだにアプリを前面に戻したら通知は出しません。拡張が同じファイルの通知を送り直しても、受信記録で受け付け済みと分かったものは通知しません。通知には保存パス・説明・ペアリングコードを載せません。実装は `src-tauri/src/arrival_notice.rs` です。

Windows の通知は、クリックすると `vrclibman://open` を開きます（トーストの `activationType="protocol"`）。アクションセンターに移ったあとの通知でも、アプリを終了したあとでも開けます。起動中のアプリには単一起動の仕組みで URL が渡り、ウィンドウを前に出します（常駐中は作り直します）。終了していればアプリが起動します。通知プラグインのクリック通知は、トーストが画面にあるあいだしか届かないため、Windows では使わず、`windows` crate で通知を直接出しています。macOS と Linux は通知プラグインのクリック通知でウィンドウを開きます。

Windows の通知は、スタートメニューのショートカットに識別子 `app.vrclibman.desktop` が付いたインストール版から出したときだけ、VRCLibMan の名前とアイコンで出ます。`target\debug` などから動かした開発版では「Windows PowerShell」として出ます。クリックで開くのは `vrclibman` を登録したアプリなので、`npm run tauri dev` では開発版が開きます。通知を止めるときは OS の通知設定で VRCLibMan をオフにします。

## BOOTH 上での表示

検索結果・ショップ・商品ページ・購入ライブラリで、アプリに登録のある商品に次の印を付けます。

- **所持**：取り込み済みバリエーションに所持の記録があります。有料購入の証明という意味ではありません。
- **登録のみ**：商品情報がアプリにあるだけで、購入を断定しません。
- **保存記録あり**：ファイルとの結び付けがアプリにあります。取得後に外部で削除・移動された可能性があり、現時点のファイル存在を保証しません。
- **保存記録なし／ファイル情報未取得**：保存やファイル情報をまだ確認できていません。
- **アバター名**：アプリに登録された所持アバターとの対応です。共通素体からの表示は「・共通素体」を付け、髪には適用しません。

アプリに登録のない商品には印を付けません。購入ライブラリでだけ「未登録」と「LibMan に登録」を出します。除外した商品は未登録と同じに扱います。

一覧のページで対応アバターのある商品があると、一覧の上に「所持アバターで絞り込む」を出します。購入ライブラリのように、BOOTH の絞り込み欄と一覧が横に並ぶページでは、その並びに列を足さず、一覧の中の先頭の商品の上に置きます。列を足すと、絞り込み欄と一覧の間に帯が挟まり、BOOTH の画面が崩れるためです。絞り込みは対応が分かっている商品だけに効き、未登録・対応未確認の商品は残します。一般の対応・非対応の判断には使わないでください。

アプリに接続できないときは、印と絞り込みを出さず、隠した商品も元に戻します。ブラウザへフォーカスが戻ったときと、一覧の追加読み込みのときに、アプリへ最新の状態を問い合わせます。設定の「商品に所持と対応アバターを表示する」をオフにすると、印と絞り込みを出しません。ダウンロード欄の「LibMan で取得」は残ります。

## 内蔵ブラウザとの違い

アプリで読み込み方を選ぶ画面の比較表（`src/importMethods.ts`）は、この表と同じ事実を、選ぶのに要る行に絞って載せています。どちらかを変えたら、もう一方も合わせます。

| 機能 | 内蔵ブラウザ | 拡張 |
| --- | --- | --- |
| ライブラリ全取得・新しい購入 | ○ | ○（新しい購入は拡張だけ） |
| 任意の商品ページを送る | × | ○ |
| 購入履歴の読み込み、購入完了の登録 | ○ | ○ |
| BOOTH のページで選んだ 1 件の取得 | ○ | ○ |
| アプリの商品カードの「ダウンロード」 | ○ | × |
| アセット更新の「今すぐ確認」でのライブラリ読み直し | ○ | × |
| 自動整理オフでの保存記録 | ○ | × |
| BOOTH 上の所持・対応アバターの表示と絞り込み | × | ○ |
| ブラウザの横に、登録済みの商品をアバターとジャンルで並べる | × | ○ |
| Cookie をアプリへ渡さない | × | ○ |

アプリの画面から拡張を動かす経路はありません。拡張からアプリの画面を動かすのは、本人が押した「アプリで開く」だけです。拡張はブラウザが開いている間だけ動きます。

## 保存・通信と復旧

Cookie やパスワードは読み出さず、アプリにも送りません。ログインを使うのは、ライブラリの一覧、購入履歴・注文詳細、本人が選んだファイルの取得だけで、どれもブラウザ自身が行います。説明の補完は Cookie を送りません。ページの表示情報は、ローカル HTTP の認証済み受信口へ照会します。ページへローカルパスやペアリングコードは渡しません。

サイドパネルのライブラリは、アプリの認証済み受信口から読みます。受信口は `POST /library/avatars`（アバターの並びと件数）、`POST /library/items`（アバター 1 体、またはアセット・ワールドの商品）、`POST /library/thumb`（商品 ID 1 つの保存済みサムネイル）、`POST /library/product`（商品 1 件の注文番号・日時・贈ったギフトの印・購入した対応版）、`POST /library/open`（「アプリで開く」）の 5 つで、ほかの受信口と同じ Origin の固定とペアリングコードを通します。返すのは商品 ID・商品名・ショップ・印・アバター名・注文番号・日時だけで、ローカルのパス・説明・URL・金額は返しません。サムネイルは、アプリのサムネイルのフォルダにある、商品 ID の名前のファイルだけを返します。`/library/open` は商品 ID を 1 つだけ受け、行き先はアプリが登録済みの商品から決めます。設定やインポートなど、ほかの画面へは移せません。これらは拡張自身の画面（ポップアップとサイドパネル）にだけ渡し、BOOTH のページの中で動く部品には渡しません。一覧と画像はブラウザに保存せず、パネルを閉じると消えます。保存するのは、最後に選んだアバター（アバターの ID）だけです。

長い読み込みは、拡張の見えない文書（offscreen 文書）で動きます。ブラウザを閉じると止まり、次に開いたときは「中断しました」と出します。読んだところまでは送り済みです。

取得を追跡する商品情報・ファイル ID・バリエーション、未送信通知（保存パスを含む）、購入完了の注文番号（最近 200 件）、最近の取り込みの件数（20 件）を `chrome.storage.local` に保持します。読み込みの進み具合と、ページから読んだ商品の題などのメモは、ブラウザを閉じると消える `chrome.storage.session` に置きます。成功した通知と対応情報は削除します。接続先の異なる通知は保留し、元の接続に戻すまで送信しません。通知の受信記録はアプリに最近 2000 件を保持します。アプリ起動時に先にファイルが回収された場合に備え、保存元・移動先・商品 ID・移動日時の対応も最近 2000 件をアプリ内に保持します。通知の取得開始日時と商品・サイズ・保存記録が一致したときだけ照合します。拡張の削除で未送信通知は消えますが、保存済みファイルは残ります。

## 確認範囲

合成データのサービスワーカー・読み込み手順・ポップアップ・サイドパネルのテスト、SQLite のテスト、Chromium でのページ上の表示・絞り込み・クリック確認を用意しています。サイドパネルのライブラリと「アプリで開く」は、見本の応答を返す Chromium のテストと画面の確認、アプリ側の受信口のテストまでで、実際の Chrome / Edge のサイドパネルとアプリをつないだ確認（Windows でウィンドウが前に出るかを含む）はまだです。実際の Chrome に拡張を読み込み、公開ページでの表示、ログインしていないライブラリでの停止、商品ページの送信を確かめています（[検証記録](verification.md)）。BOOTH にログインした状態での購入ライブラリの「すべて読み込む」と購入履歴の読み込みも、内蔵ブラウザの結果と件数で比べています。購入完了ページ、実際の取得、Edge、macOS / Linux は別途確認が必要です。

先行ツールからコードや素材を取り込んでいません。外部コードを新たに採用する際は、明示されたライセンスと利用条件を先に確認します。
