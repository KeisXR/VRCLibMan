# 画面の通信と読み込みの復旧

## 設定画面

一般設定、編集用の対応表、連携状態、カタログ、Appleモデルの状態、アプリ版は独立して読み込む。一般設定を読めた時点で本文を表示し、補助情報の失敗で本文全体を隠さない。編集用の対応表は読み込むまで編集欄を出さない。

各読み取りは10秒で待機を区切り、失敗した情報の名前と「もう一度読み込む」を設定ページに表示する。タイムアウト後の古い応答は適用しない。再読み込み時も自動保存コントローラの世代と未保存の下書きを保持し、読み直した保存値で編集中の値を上書きしない。

## Windowsの通信経路

`src/main.tsx` はローカルのメイン画面と操作バーの起動時に `installIpcRecovery` を実行する。WindowsのTauriは `http://ipc.localhost/<command>`（HTTPS構成ではHTTPS）のfetchを使う。このfetchが終了しない場合、Tauri本来の失敗時処理へ進めない。

`src/ipcRecovery.ts` は、設定画面の読み取り、ブラウザ状態、パネル静止画、パネル配置通知だけに5秒の期限を付ける。期限を超えたfetchを中断・拒否すると、Tauri 2.12.5自身が認証キー付きのpostMessageへ切り替え、対象の要求を再送する。その後の呼び出しもTauriが同じ経路を使う。アプリが認証キーを取り出したり、独自のIPCメッセージを作ったりはしない。

対象は明示したコマンドと `browser_action` の `panelArea` だけ。保存、インポート、ダウンロード、タブ追加、移動などは、応答が失われても実行済みの可能性があるため、この仕組みで中断・再送しない。すでに応答待ちになった変更処理を自動で再実行することもない。BOOTHなど外部のHTTP要求、呼び出し元がAbortSignalを指定した要求、見本API、macOS/Linuxの別スキームには適用しない。

診断のconsole警告はタイムアウトした固定のコマンド名と、パネル通知の再試行だけを出す。引数、商品名、パス、Cookie、ペアリングコード、応答本文は記録しない。両方の通信経路やネイティブ処理自体が停止した場合の復旧を保証するものではない。

## 右パネル

`src/panelReporter.ts` は最新の矩形・表示状態だけを保持する共有の送信キュー。送信中は次を重ねず、成功した状態だけを重複抑止の基準にする。失敗したら基準を無効にして500ms後に最新状態を送る。パネルのアンマウント時にも最後の非表示をキューへ渡すため、コンポーネントが消えた後も再試行できる。

`useDockedArea` は破棄済みかを測定と予約の両方で確認する。MutationObserverの遅れた通知などが、パネルを閉じた後に古い矩形を送って表示を戻すことを防ぐ。ブラウザ状態の読み取りも同時に積み上げず、取得中に更新通知が届いた場合は完了後にもう一度確認する。

## 検証の区別

`test/ipc-recovery.test.mjs` はTauri 2.12.5の実際の `scripts/ipc-protocol.js` を保存したfixtureで、応答しないfetchから認証付きpostMessageへの切り替えを確認する。fixtureには上流のMIT/Apache-2.0の表示を残す。Tauriの通信スクリプトを更新する場合は、fixtureと復旧の前提も照合する。

設定の待機・再試行・下書きの保持と、パネルの失敗・遅い応答・アンマウント後の非表示は合成APIの試験で確認する。長時間放置後の実WebView2障害そのものの再現・復旧とは区別し、実施結果は [検証記録](verification.md) に残す。
