# VRCLibMan

VRCLibMan は、所有している VRChat / BOOTH 向けアセットを整理するローカルのデスクトップアプリです。アバター、衣装、髪、アクセサリ、テクスチャ、ギミック、ワールド、その他を扱います。Windows と Apple Silicon Mac 向けで、Tauri v2 / Rust / React で作られています。

商品情報をインポートし、説明文からカテゴリと対応アバター名を抽出し、手元のファイルと商品を対応付けます。対応関係は確認・修正でき、同じ素体として登録したアバター間の衣装も表示します。Unity への導入、購入、クラウド同期をするアプリではありません。

## データと通信

- 商品、分類、対応表、設定はアプリデータ内の `library.sqlite` に保存します。サムネイルは同じ場所の `thumbs`、ダウンロードしたファイルは指定したライブラリフォルダに置きます。
- Windows のアプリデータは `%APPDATA%\app.vrclibman.desktop`、macOS は `~/Library/Application Support/app.vrclibman.desktop` です。アンインストールしてもこのデータは自動では消しません。
- クラウド用のサーバーや同期機能はありません。分類は通常、同じ PC の Ollama に商品タイトルと説明文を送ります。接続先は `http://127.0.0.1`、`localhost`、`::1` のいずれかに制限されています。
- macOS 27.2 以上で利用可能と判定された場合は、Ollama の代わりに Apple のオンデバイスモデルを選べます。この処理も端末内です。
- 外部へ通信するのは、BOOTH / pixiv のページをブラウザで開くとき、BOOTH の公開ページや画像を拡張が補完するとき、サムネイルを取得するとき、内蔵ブラウザで明示したファイルをダウンロードするとき、Ollama のモデルを取得するとき、および設定から同梱対応表の更新を実行したときです。内蔵ブラウザでログインすれば、通常のブラウザと同様に認証情報やセッション情報は BOOTH / pixiv との通信に使われます。VRCLibMan 独自の外部サービスへライブラリを送る処理はありません。

## BOOTH / pixiv へのアクセス

インポート方法は 2 つあります。

### Chrome 拡張（既定）

拡張は、ユーザーが Chrome または Edge で BOOTH にログインした状態で、開いている商品ページまたは購入ライブラリを読みます。「このページを送る」「ライブラリをすべて送る」「新しい購入だけ送る」の操作時に商品情報を抽出し、アプリの `127.0.0.1:17321` へ送ります。

ライブラリの全取得と公開商品の説明補完は、ポップアップから設定した間隔（1.0秒・0.5秒・0.25秒）でBOOTHへ順次アクセスします。初期値は1.0秒で、0.25秒の高速モードはアカウント制限・サーバー負荷のリスクが高いため明示確認が必要です。HTTP 429 / 503 は Retry-After を尊重して最大 1 回だけ再試行し、指定待機が 60 秒を超える場合は再試行せず中止します。短い説明文は、ログイン Cookie を付けずに公開 HTML または公開 JSON から補います（HTML が 401 / 403 の場合は JSON へのフォールバックをしません）。拡張はパスワードや Cookie をアプリへ送りません。アプリが不在なら起動を試し、それでも送れない場合はインポート用 JSON を保存します。

### 内蔵ブラウザ（任意、既定はオフ）

設定で有効にすると、アプリ内の専用ウィンドウで BOOTH / pixiv にログインできます。メールアドレスとパスワードによるログインとパスキーによるログインは、表示されたサイトの画面上で行います。ログイン状態はアプリ専用の WebView データストアに保持され、画面にはログイン中のアカウントを表示します。「ログアウトしてセッションを消す」でこの状態を削除できます。

内蔵ブラウザは、現在のライブラリページのインポートと、ボタンを押したときのライブラリ全ページ・ギフトページの順次インポートができます。未ダウンロードのファイルで「ダウンロード」を押すと、その 1 件だけを、保存したログインセッションを使って取得します。この処理では WebView の BOOTH Cookie を読み、BOOTH へのダウンロード要求だけに付けます。署名付きダウンロード先への遷移には追従しますが、Cookie をログへ書いたり別サービスへ送ったりはしません。

内蔵ブラウザを有効にする際、アプリはアカウントの制限・停止を含むリスクを警告し、確認を求めます。この機能はユーザー自身のアカウント上の操作を自動化するため、BOOTH / pixiv の利用規約に反する、または規約上グレーと判断される可能性があります。利用するかどうかと結果の責任はユーザーにあります。

負荷と意図しない取得を抑えるため、ページを並列に巡回せず、ライブラリ全取得を押した場合だけ、ブラウザ画面で選択した1.0秒（初期値）・0.5秒・0.25秒の間隔で順番に移動します。0.25秒への変更時はリスク警告を表示します。ファイルの一括ダウンロードや自動ダウンロードはありません。「ダウンロード」を押した 1 件だけを取得し、年齢確認を自動通過しません。

## 利用規約とアカウントへの注意

VRCLibMan は BOOTH / pixiv / VRChat の非公式アプリです。購入履歴の自動取得や、内蔵ブラウザでのログイン・Cookie を使用したファイルのダウンロードは、サービスの利用規約や運営の判断によって制限される可能性があります。**このアプリは規約への適合や、アカウント停止などが起きないことを保証しません。**

BOOTH へのアクセス間隔は拡張機能と内蔵ブラウザでそれぞれ設定できます。**1.0秒を推奨**し、0.25秒はアクセス制限や負荷のリスクが高い設定として、警告への確認後にのみ有効にできます。0.25秒なら安全にアクセスできるという意味ではなく、必要に応じてBOOTH側の制限が優先されます。

使用前に [BOOTH ガイドライン](https://booth.pm/guidelines) と [pixiv / BOOTH の利用規約](https://policies.pixiv.net/) を確認してください。内蔵ブラウザは初期状態で無効です。

## ローカル HTTP 受信口

アプリは IPv4 ループバックの `127.0.0.1:17321` だけで待ち受けます。LAN やインターネットには公開しません。受け付けるのは Chrome 拡張形式の Origin と、設定画面の 8 文字のペアリングコードを Bearer token として持つ要求だけです。最初に成功した拡張の Origin を固定し、コードを再発行すると固定を解除します。

受信する内容は次のとおりです。

- 到達確認
- 商品・購入ライブラリの JSON インポート
- インポート済み商品 ID の照会
- ダウンロードの自動整理設定の読み書き
- 拡張でユーザーが開始したダウンロードの完了通知と、保存ファイルのパス・商品 ID・ファイル情報

Web ページからの要求は、コードが合っていても Origin 検査で拒否します。認証失敗が続くと一時的に受信を制限します。

## ファイルの保存と常駐

「ダウンロードを自動整理」は既定でオフです。有効にすると、拡張または内蔵ブラウザでユーザーが開始した対象ファイルを、まず OS の `Downloads/VRCLibMan/<商品ID>/` に置き、設定したライブラリフォルダへ移します。商品 ID、直下のファイル、正規化後のパスを検査し、別の場所、サブフォルダ、`..`、シンボリックリンクは受け付けません。

アプリは起動時に `Downloads/VRCLibMan` を 1 回だけ調べます。前回アプリが停止していて移動できなかった、安全に特定できるファイルはライブラリへ移し、それ以外は残してインポート画面に理由を表示します。

バックグラウンド動作とログイン時の起動はどちらも既定でオフです。バックグラウンド動作を有効にすると、メインウィンドウを閉じてもプロセスと HTTP 受信口を残し、Windows のトレイまたは macOS のメニューバーから再表示・終了できます。ログイン時の起動はバックグラウンド動作が有効な場合だけ設定でき、ウィンドウを開かずに起動します。

## インストールと初期設定

配布物は Windows 用の未署名 NSIS インストーラと、Apple Silicon / macOS 14 以降用の未署名・未公証 dmg です。OS の警告が出る場合があります。Intel Mac 用ビルドはありません。Windows 10 では WebView2 が別途必要になる場合があります。

1. アプリをインストールして起動します。
2. 通常は [Ollama](https://ollama.com/) をインストールして起動します。推奨・既定モデルは `qwen3.5:9b` です。
3. セットアップで分類用モデルを選びます。軽量な選択肢は `qwen3.5:4b`（容量約 3.3〜4.0 GB、メモリ 8 GB 以上が目安）、推奨・既定は `qwen3.5:9b`（容量約 6.6〜7.6 GB、メモリ 16 GB 以上が目安）です。`gemma4:12b`（容量約 7.5 GB、メモリ 16 GB 以上が目安）や導入済みモデル、手入力も選べます。既存ユーザーが保存したモデル選択は引き継ぎます。選ぶだけでは取得せず、取得ボタンの容量確認後にだけダウンロードします。qwen3.5 の実モデルでの品質とメモリ使用量は未検証です。macOS 27.2 以上で Apple のオンデバイスモデルが利用可能なら、Ollama を使わない選択もできます。
4. ライブラリフォルダを設定します。必要ならダウンロードの自動整理、バックグラウンド動作、ログイン時の起動を個別に有効にします。

設定画面の変更は自動で保存・適用します。入力エラーなどで保存できなかった場合は、画面に未保存の表示と理由を出します。

VRChat・Unity に関係のない商品は、インポート画面の「商品を管理・除外」、確認画面や商品詳細の「除外」から一覧・分類の対象外にできます。再インポートしても除外は維持され、「商品を管理・除外」から元に戻せます。商品情報と手元のファイルは削除しません。

### 拡張のインストール

1. Release の拡張 zip を展開するか、このリポジトリの `extension` フォルダを使います。
2. Chrome / Edge の拡張機能管理画面で開発者モードを有効にし、「パッケージ化されていない拡張機能を読み込む」から、`manifest.json` が直下にあるフォルダを選びます。
3. アプリの設定に表示されたペアリングコードを拡張のポップアップへ保存します。
4. BOOTH にログインし、対象ページで送信ボタンを押します。

## ソースからのビルドとテスト

必要なものは Node.js、Rust（rustup）、各 OS のビルドツールです。Windows は Visual Studio 2022 Build Tools の C++ ワークロード、macOS は Xcode Command Line Tools と `aarch64-apple-darwin` Rust ターゲットが必要です。通常の分類を試す場合は Ollama も必要です。

```sh
npm ci
npm run tauri build
```

macOS の Apple Silicon 向けを明示する場合は次のとおりです。

```sh
rustup target add aarch64-apple-darwin
npm run tauri build -- --target aarch64-apple-darwin
```

テストとフロントエンドのビルドは次で実行します。

```sh
npm test
cargo test --manifest-path src-tauri/Cargo.toml
npm run build
```

`npm run tauri dev` で実アプリを開けます。`npm run dev` は UI 確認用の見本データだけを表示し、SQLite、分類、フォルダ調査は動きません。

## リリースの作り方

`v*` タグを push すると `.github/workflows/release.yml` が動き、Windows の NSIS インストーラ、Apple Silicon の dmg、拡張 zip を載せた**下書き**の Release を作ります。公開は手で行います。

1. アプリの版を `package.json`、`package-lock.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock` で揃えて上げ、main にマージします。拡張の版（`extension/manifest.json`）はアプリとは独立しており、拡張を変えたときだけ上げます。
2. main の最新でタグを打って push します（例: `git tag v0.1.3 && git push origin v0.1.3`）。
3. Actions の release が終わったら、Releases の下書きで 3 つのファイルと本文を確認し、「Publish release」を押します。

タグとアプリの版が違う場合、版が揃っていない場合、タグのコミットが main に無い場合、同じタグの Release がすでに公開済みの場合は、ビルド前に失敗します。Actions の「Run workflow」から手動で実行すると、タグも Release も作らずに同じビルドだけを行い、成果物を workflow の Artifacts に置きます。Mac は Apple のオンデバイスモデル補助プログラムに macOS 27.2 SDK が要るため、GitHub の `xcode-27` ランナーでビルドします。

## 既知の制限

- BOOTH の DOM やログイン手順が変わると、拡張と内蔵ブラウザのインポートが動かなくなる可能性があります。
- 説明文による分類は誤ることがあります。未解決・要確認キューと手動編集を前提にしています。登録されていない素体関係を推測しません。
- 非公開・公開終了・年齢確認が必要な商品の説明は取得できない場合があります。年齢確認は自動処理しません。
- 内蔵ブラウザの全取得はライブラリとギフトを逐次処理しますが、失敗、ログイン切れ、年齢確認、中止時には途中で止まります。
- 内蔵ブラウザのログイン状態は端末内に残ります。共有 PC では使用後にアプリ内からログアウトしてください。
- 配布物に正式なコード署名・公証はなく、macOS は Apple Silicon のみです。
- リモートライブラリは UNC パスまたはマウント済み共有を対象とするファイルコピー機能で、クラウド同期や競合解決はありません。

### 読み込みとバージョンの確認

セットアップと設定の「BOOTH の読み込み方」で Chrome / Edge の拡張、内蔵ブラウザ、両方から選べます。選択はその場で保存します。拡張 zip の入手先、展開した manifest.json のあるフォルダの読み込み、ペアリングの手順もアプリ内にあります。内蔵ブラウザだけを選んだ場合、拡張のコードは表示しません。ログイン状態はアプリ専用の WebView に残り、設定からログアウトして消せます。

インポート画面は「BOOTH から読み込む → 分類 → 手元のファイル」の順です。最後の受信日時と件数を確認できます。「すべて再分類」は既存の結果を上書きしうる旨の確認後に実行します。JSON の予備の読み込み、無料商品の URL 追加、サムネイル保存は下部の「その他」にあります。

アプリの版はサイドバーと設定の「データ → バージョン」、拡張の版は拡張ポップアップで確認できます。設定には想定する拡張の版と最後に通信した拡張の版も表示します。版が異なる場合は Releases の拡張 zip を展開して更新し、ブラウザの拡張管理画面で読み込み直してください。旧拡張が版を通知しない場合は「未確認」になります。版情報は既存の 127.0.0.1 の通信でやり取りし、外部への更新確認はしません。
