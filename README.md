# VRCLibMan

持っている VRChat / Booth のアバターと、同じ素体で着られる衣装・髪・ギミックを、手元の PC だけで整理するアプリです。

Booth のパスワードやクッキーは持ちません。ブラウザ拡張が、すでにログインしているページの今見えている商品だけを JSON にします。アプリはその JSON を読みます。分類の文章抽出だけを、同じ PC の Ollama に頼みます。どの商品がどのアバターか、どのアバターが同じ素体かは、アプリ内の対応表で決めます。

やらないことは次のとおりです。

- Booth へのログイン、購入、自動ダウンロード
- Unity への転送
- クラウド同期
- 対応表に無い素体関係の推測

## 必要なもの

- Node.js
- Rust（rustup）。Windows では Visual Studio 2022 Build Tools の C++ ワークロード。Mac では Xcode Command Line Tools
- Windows では WebView2（Windows 11 には入っています）。Mac は macOS 14 以上の WebKit
- [Ollama](https://ollama.com/)。分類の既定モデルは `gemma4:12b` です。`ollama pull gemma4:12b`
- 軽い代替は `ollama pull qwen3:4b`。これより小さいモデルは勧めません。設定のモデル名で、導入済みのモデルを選べます。すでに保存したモデル名は、更新しても上書きしません。
- メモリは 16GB 以上を想定しています。それ未満の Mac 向けに既定モデルは切り替えません。

## インストール（Windows）

公開された GitHub Release から、`VRCLibMan_*_x64-setup.exe` を実行します。これは NSIS のインストーラで、署名は付いていません。SmartScreen が「Windows によって PC が保護されました」と出すことがあります。「詳細情報」から「実行」を選んで進めてください。

現在のユーザーだけに入ります。管理者権限は要りません。実行ファイルは `%LOCALAPPDATA%\VRCLibMan\VRCLibMan.exe` です。WebView2 が無い Windows 10 では、インストーラが小さなブートストラッパをダウンロードして入れます。そのときだけネットが要ります。Windows 11 には WebView2 が入っています。

インストールしたアプリと `npm run tauri dev` は、どちらも識別子 `app.vrclibman.desktop` です。そのためライブラリ `%APPDATA%\app.vrclibman.desktop\library.sqlite`（サムネイルは同じ場所の `thumbs`）と、WebView2 のプロファイル `%LOCALAPPDATA%\app.vrclibman.desktop\EBWebView` を共有します。開発中のウィンドウは、入っているアプリと同じデータベースを開きます。`npm run dev` の見本データはこの場所を使いません。

アンインストールはレジストリの `HKCU\Software\VRCLibMan` を消します。上のライブラリと WebView のフォルダは残します。

同じ Release の `vrclibman-booth-export-*.zip` が Chrome 拡張です。展開すると直下に `manifest.json` があります。`chrome://extensions` の「パッケージ化されていない拡張機能を読み込む」で、そのフォルダを指定します。

拡張とアプリのつなぎ方は次の「Booth から送る」にあります。アプリは `127.0.0.1:17321` だけを待ち、Booth 自身は取りに行きません。

手元でインストーラを作る手順は、下の「開発」にあります。

## インストール（Mac）

対応するのは Apple Silicon の macOS 14 以降だけです。Intel Mac 用のビルドはありません。公開された GitHub Release の `dmg` を開き、`VRCLibMan.app` をアプリケーションフォルダへドラッグします。署名も公証もしていません。ad-hoc 署名だけです。ad-hoc 署名なので、再ビルドごとにフォルダの許可を求められることがあります。

初めて開くとき、macOS が止めることがあります。システム設定の「プライバシーとセキュリティ」で「このまま開く」を選ぶか、ターミナルで次を実行してください。

```sh
xattr -dr com.apple.quarantine /Applications/VRCLibMan.app
```

ライブラリは `~/Library/Application Support/app.vrclibman.desktop/library.sqlite` です。サムネイルは同じ場所の `thumbs` です。内蔵ブラウザのログイン状態は、メイン画面とは別の WebKit データストアに残します。ログアウトはそのデータストアを消します。

`vrclibman://` は、`.app` を `/Applications` に置いたときだけ動きます。デスクトップやダウンロードフォルダに置いただけでは、拡張からの起動に使えません。

拡張の zip は Windows のリリースと同じです。Chrome への読み込み方は Windows の節と同じです。

## 起動

開発中は次でウィンドウを開きます。

```powershell
npm install
npm run tauri dev
```

`npm run dev` でポート 1420 を開いたまま `npm run tauri dev` を実行すると、Vite が二重に起動して失敗します。先に `npm run dev` を止めてから実行してください。`npm run tauri dev` はインストール版と同じ識別子なので、上に書いた `%APPDATA%` のデータベースと WebView プロファイルを開きます。

画面だけの確認は `npm run dev` で http://localhost:1420 を開きます。このとき出るのは見本データで、抽出・フォルダ調査・Ollama は動きません。

## Booth から送る

1. Chrome か Edge で `extension` フォルダを「パッケージ化されていない拡張機能」として読み込む
2. VRCLibMan の設定に出るペアリングコードを、拡張のポップアップに一度貼って「コードを保存」を押す。最初に届いた拡張だけを覚えます。コードを作り直すと、その結び付きも外れます
3. Booth に自分でログインする。ポップアップの「ライブラリを開く」は `https://accounts.booth.pm/library` を開くだけで、自動では読みません
4. 商品ページかライブラリを開いて「このページを送る」または「ライブラリをすべて送る」を押す
5. アプリが閉じているときは、拡張が `vrclibman://import` で起動してから数秒送り直します。それでも届かなければ JSON を保存するので、アプリの「取り込み」へドロップします
6. 「未抽出を分類」で Ollama にカテゴリと、文中のアバター名だけを抜かせる
7. アバターを開くと、その素体と共通素体の衣装が見える

設定の「内蔵ブラウザを有効にする」は、別ウィンドウで BOOTH に自分でログインし、今開いているライブラリのページだけを取り込むモードです。既定ではオフです。有効にする前に、アカウントへのリスクを確認するダイアログが出ます。年齢確認は自動で進みません。ログアウトは、そのウィンドウのログイン状態だけを消します。

説明文の補完は、拡張が商品の公開ページを `credentials: "omit"` で1件ずつ取ります。年齢確認で本文が落ちるときは、同じ条件で商品の JSON を読みます。ログイン中のセッションは、説明の補完には送りません。ライブラリ全ページの読み取りだけ、すでにブラウザで開いているログインを使います。

Ollama の接続先は `http://127.0.0.1` か `localhost` だけです。温度は 0.1 固定です。初期モデルは `gemma4:12b` で、目安として 8GB の VRAM を使います。`qwen3:4b` は軽い代替で、設定から導入済みのモデルを選べます。分類で何をアバター名にし、何を確認に残すかは `AGENTS.md` の「抽出と確認の契約」に書いてあります。

## 初期データ

アバター名の対応表には、えりんぎ氏の「もちふぃった～プロファイル一覧」のスナップショットを同梱しています。出典、規約、取得日は `THIRD_PARTY_NOTICES.md` と設定画面にあります。起動のたびに取りには行きません。設定の「対応表を更新」を押したときだけ、GitHub の raw を1回取得します。共通素体シート（スペキュラム合金さん）はライセンスが確認できないため入れていません。

素体グループとして最初から入っているのは、作者の商品説明で衣装の着せ替えができると確認できた「あまとうさぎ共通素体」（ライム、プラム、シフォン、ショコラ）だけです。マヌカ、しなの、セレスティア、ミルティナ、桔梗、ルルネは別名だけで、同じ素体には入れていません。プロファイル一覧の `bodyBase` はメモとして残すだけで、素体グループにはしません。関係を足すときは設定の対応表で、根拠が分かるメモと一緒に追加してください。削除した素体の初期データは、起動のたびに戻りません。「初期データを追加」で足りない行だけ戻ります。同梱したアバター名は初期データなので、設定の一覧からは削除できません。別名の編集はできます。

ライブラリの商品 ID がプロファイル一覧の商品 ID と一致したアバターは、Ollama を使わず所持として記録します。一覧にないアバター本体は確認画面の「所持アバターにする」で手で付けます。アバター画面は「持っているアバター」と「衣装の対応先」を分け、「所持だけで絞る」で所持だけにできます。

初回起動時はセットアップが出ます。既定のモデルは `gemma4:12b` で、画面には今の設定も出します。サイズは、そのモデルが Ollama に入っているときだけ表示します。続けて拡張の読み込み方、ペアリングコード、ライブラリを開くボタンです。スキップできます。商品が既にあるか、拡張とペアリング済みのデータベースでは、更新後にこの画面は出ません。設定の「セットアップを再表示」でやり直せます。

拡張の「ライブラリをすべて送る」は、これまでどおり全ページを読み、既にある商品も更新します。「新しい購入だけ送る」は新しい購入から読み、アプリが取り込み済みと答えた商品に当たったページで止まります。ページの間隔は、説明の補完と同じく 250 ミリ秒以上です。

フォルダ調査は、ドライブ直下、Windows、Program Files を拒否します。Mac では加えて `/System`、`/Library`、`/Applications`、`/private`、ホームフォルダそのもの、`/Volumes` そのものを拒否します。深さ 8、2 万件までです。

## 手元のファイル

購入したバリエーションと、ダウンロード欄のファイル名は、ライブラリか商品ページを送ったときだけ記録します。ライブラリに出ているバリエーションは購入済みです。商品ページでダウンロード欄が無いバリエーションは未購入としてグレーにします。一度購入済みにした名前は、あとから届いた「未購入」では戻しません。

各ファイルは「ローカルにある」「リモートにだけある」「未ダウンロード」のどれかです。リモートは設定したフォルダ（UNC やマウントした共有）だけで、切れているときは約 1.5 秒で諦めて未ダウンロードにします。画面は固まりません。「ローカルに取ってくる」と「リモートに送る」は、押したファイルだけをコピーします。アプリが BOOTH からファイルを取りに行くことはありません。

拡張の `downloads` 権限は二つの用途です。アプリが起動していないとき、書き出した JSON を保存ダイアログで手元に残します。設定とポップアップの振り分けをオンにしたときだけ、自分で押した BOOTH の `.unitypackage` / `.zip` / `.rar` / `.7z` / `.vrm` を、この PC のダウンロードフォルダの `VRCLibMan/商品ID/` に置き、完了後にアプリが設定のライブラリフォルダへ移します。受け付けるのはそのフォルダの直下だけです。別の場所にある `VRCLibMan` や、商品 ID が違うフォルダ、サブフォルダ、シンボリックリンクは移しません。振り分けは既定でオフで、オンにするにはライブラリフォルダが必要です。拡張から `chrome.downloads.download` で BOOTH のファイルを始めることはしません。

ライブラリに無い無料商品は、商品ページを送る、振り分け中の無料ダウンロードが届く、取り込み画面に URL を貼る、のどれかで項目になります。URL を貼っただけではページを開きません。

## 開発

```powershell
npm test
cargo test --manifest-path src-tauri/Cargo.toml
```

`npm test` は拡張のページ解析です。`cargo test` は取り込み、名前の解決、ファイル名の突合、画面用の集計です。

Windows でインストーラを手元で作るときは、上の「必要なもの」に加えて NSIS を Tauri が初回に取ります。

```powershell
npm install
npm run tauri build
```

できたファイルは `src-tauri\target\release\bundle\nsis\VRCLibMan_0.1.3_x64-setup.exe` です。中の実行ファイルは `VRCLibMan.exe` です。ARM の Windows では `x64` が `arm64` になります。版は `package.json`、`src-tauri\tauri.conf.json`、`src-tauri\Cargo.toml` の `version` を同じにしてください。GitHub へ載せるときは、その版のタグ `v0.1.3` を push します。workflow が下書き Release に、未署名の setup.exe、Apple Silicon の dmg、拡張の zip を置きます。コード署名の秘密情報は入れていません。NSIS は現在のユーザー向けに `vrclibman://` を登録し、アンインストールでその登録を外します。`npm run tauri dev` は同じプロトコルを開発用の実行ファイルへ付け替えるので、配布版を試すときはインストールし直してください。

Mac で手元の dmg を作るときは、Xcode Command Line Tools、rustup の `aarch64-apple-darwin`、Node、Ollama を入れます。Intel 用ターゲットは要りません。

```sh
xcode-select --install
rustup target add aarch64-apple-darwin
npm install
npm run tauri build -- --target aarch64-apple-darwin
```

できたファイルは `src-tauri/target/aarch64-apple-darwin/release/bundle/dmg/` の dmg です。署名は ad-hoc（`signingIdentity` が `-`）だけで、公証はしません。`vrclibman://` を試すときは、できた `.app` を `/Applications` に置いてから開いてください。
